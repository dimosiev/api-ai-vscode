# Устройство dimosi — для ИИ-агента, который меняет этот код

Читай этот файл перед правкой модуля. Правила работы, запреты и команды — в [CLAUDE.md](../CLAUDE.md): он главнее. Руководство владельца — [РУКОВОДСТВО.md](РУКОВОДСТВО.md), история находок — [AUDIT.md](AUDIT.md).

Если описание здесь разошлось с кодом, верь коду и исправь описание в том же коммите.

## 1. Карта

Монорепозиторий на npm workspaces. TypeScript, сборка esbuild, тесты vitest.

| Пакет | Что это | От чего зависит |
|---|---|---|
| `packages/core` (`@dimosi/core`) | Ядро: цикл агента, инструменты, доступ, подтверждения, сервисы нейросетей, правила, обновления | Только Node и два SDK (Anthropic, OpenAI). **Никогда не импортирует `vscode`** |
| `packages/vscode` (`dimosi`) | Расширение: `src/` работает в процессе расширений VS Code, `webview/` — в браузерной панели чата | `core`, `vscode` |
| `packages/cli` (`@dimosi/cli`) | Терминальная версия | `core` |
| `scripts/` | Упаковка, выпуск, ключ подписи | `core/src/update.ts` |

Ядро не знает, где оно запущено. Всё, что отличает VS Code от терминала, хост передаёт ядру через интерфейсы:

| Интерфейс (где объявлен) | VS Code | CLI |
|---|---|---|
| `ApprovalHandler` (`permissions.ts`) — спросить владельца | `WebviewApproval` (`approval.ts`): карточка в чате | вопрос в терминале (`cli/src/index.ts`) |
| `FileAccess` (`tools/index.ts`) — читать и писать файлы | `editorFiles`: открытый файл через редактор, остальные через диск | `diskFiles` |
| `ProblemWatcher` (`tools/index.ts`) — ошибки редактора после правки | `EditorProblems.watch` (`problems.ts`) | нет |
| `CommandRuleStore` (`commandRules.ts`) — запомненные «Всегда» | `globalState` (`vscode/src/commandRules.ts`) | `allowed-commands.json` |
| `RuleTrust` (`rules.ts`) — доверие к правилам проекта | окно `ruleTrust.ts` | вопрос в терминале |
| `KeyStore` (`secrets.ts`) — API-ключи | SecretStorage / Keychain (`keyStore.ts`) | зашифрованный `keys.aienc` |
| `LogSink` (`log.ts`) — журнал | канал «Вывод → dimosi» | `~/.config/dimosi/dimosi.log` |
| `WebAccess` (`tools/web.ts`) — сеть для `fetch_page` | настоящая | настоящая (в тестах подменяется) |
| `ImageMaker` (`tools/image.ts`) — рисующая модель для `generate_image` | `polzaImages` с ключом Polza AI из Keychain (`settings.ts`, `buildImages`), при любом сервисе разговора | `polzaImages`, только когда выбран сервис Polza AI |

## 2. Путь одного сообщения

1. **Панель → расширение.** Браузерный код (`webview/main.ts`, `composer.ts`, `cards.ts`) шлёт сообщение; типы обеих сторон — в `vscode/src/protocol.ts` (`FromWebview`, `ToWebview`). `ChatViewProvider.onMessage` (`chatView.ts`) считает панель недоверенной: команды только из `PANEL_COMMANDS`, пути проверяются через `resolvePath`.
2. **Подготовка хода** (`chatView.ts`): читает настройки (`settings.ts`), собирает `Provider` с ключом (`buildProvider`), создаёт `Agent` один раз на папку (при смене папки — заново), перед каждым ходом обновляет его поля: сервис, модель, `maxSteps`, `sandbox`, `extraFolders`, `planFirst`, `gate.mode`.
3. **`Agent.run`** (`core/src/agent.ts`). Второй ход при идущем первом отклоняется. Дальше `runTurn`:
   - сообщение владельца дописывается в историю (в режиме плана — с пометкой `PLAN_NOTE`);
   - правила перечитываются (`loadRules`); структура проекта, дата и доступ (`AccessPolicy`) берутся **один раз на чат**; собирается системная инструкция (`buildSystemPrompt`);
   - цикл до `maxSteps` шагов: если история больше 70% окна — старые результаты инструментов заменяются пометкой до 40%; запрос к сервису (`provider.stream`), текст идёт событиями `text`; вызовы инструментов выполняются **по очереди**; их результаты кладутся одним сообщением `user`; нет вызовов — ход окончен.
   - Запрос, упавший до первого слова, повторяется до 2 раз; переполнение контекста — обрезка и один повтор; «Стоп» — пометка о том, что владелец успел увидеть.
4. **Инструмент** (`executeTool`, `core/src/tools/index.ts`). Для записи: `resolvePath` (доступ) → `assertWritable` (`.git`) → `assertNotSecret` → чтение старого текста → `gate.check` (вопрос владельцу) → `resolvePath` ещё раз → `files.writeText` → ошибки редактора → `onFileChange`. Любая ошибка становится результатом `isError`, цикл не падает.
5. **Подтверждение** (`PermissionGate.check`, `permissions.ts`), порядок проверок важен:
   1. предупреждение: особо важный файл (`protectedPathWarning`), опасная команда (`dangerousCommandWarning`), скрытые символы;
   2. веб-страница (`checkSite`): новый сайт спрашивается всегда; на разрешённом сайте — адрес с длинной частью после `?` (`pageAddressWarning`);
   3. режим плана: отказ без вопроса для любой записи и любой команды, запомненные через «Всегда» тоже;
   4. есть предупреждение — вопрос **всегда**, «Всегда» не запоминается;
   5. `auto` — разрешено;
   6. запись: «Всегда» до нового чата; команда: запомненное правило (`ruleMatches`) или вопрос.
6. **Обратно в панель.** `chatView.ts` переводит события агента (`AgentEvent`) в сообщения `ToWebview` через `post()`. `Transcript` (`chatStore.ts`) запоминает показанное, `ChangeTracker` (`changes.ts`) — изменённые файлы для отката. Чат сохраняется в `chat.json` в служебной папке VS Code (`context.storageUri`).

В CLI шаги 1–2 и 6 заменяет `cli/src/index.ts`: тот же `Agent`, события печатаются в терминал.

## 3. Модули ядра (`packages/core/src`)

- **`agent.ts`** — цикл (выше). `restore()` продолжает сохранённый чат и закрывает вызовы инструментов без результата. `trimToolResults` меняет только результаты инструментов.
- **`types.ts`** — формат истории, общий для всех сервисов (`Message`, `Part`). `Message.providerData.raw` — исходный ответ сервиса; при том же сервисе и модели отправляется назад как есть.
- **`access.ts`** — единственное место, где решается, что агенту доступно. `createAccess` проверяет папки вне проекта (`checkFolder`: не домашняя папка, не закрытая и не содержащая закрытых), `resolvePath` — путь от модели (ссылки раскрываются, `read`/`write`), `HOME_PRIVATE` закрыты всегда. `showPath` — как путь показан: относительный в проекте, полный вне его. `relativeInFolder` — путь внутри той открытой папки, где файл лежит на самом деле.
- **`tools/index.ts`** — описания инструментов (`TOOL_DEFINITIONS`), исполнители (`HANDLERS`), подписи для интерфейса (`describe`). `diskFiles.writeText` пишет через временный файл и переименование; файл без права записи не трогает, файл с жёсткой ссылкой пишет на месте. Поиск идёт в отдельном потоке с лимитом 15 с. Команда запускается в своей группе процессов, по таймауту и «Стоп» убивается всё дерево.
- **`tools/sandbox.ts`** — профиль `sandbox-exec` (macOS) строится из того же `AccessPolicy`; `commandEnv` убирает из окружения команд всё похожее на ключи. Правила в профиле упорядочены: более поздняя строка побеждает.
- **`tools/workspace.ts`** — обход файлов с учётом `.gitignore` (упрощённым), `isSecretFile` и те же имена для песочницы (`secretPathPatterns`).
- **`tools/web.ts`** — `fetch_page`: `parsePageUrl` (только https, стандартный порт, имя сайта), `assertPublic` (не локальная сеть; 198.18.x.x считается публичным из-за VPN владельца), перенаправления только внутри сайта, до 2 МБ и 40 тыс. знаков. `stripMarkup` убирает разметку за один проход; кодировка — из ответа сайта или `<meta charset>`.
- **`tools/image.ts`** — `generate_image`: `polzaImages` обращается к Media API Polza AI (`POST /media`, опрос `GET /media/{id}`, скачивание файла без ключа и только по https), `imageFormat` узнаёт картинку по первым байтам. Сам инструмент — в `tools/index.ts`: путь через `resolvePath`, только новый файл `.png/.jpg/.webp`, окончание исправляется по настоящему формату, запись на диск напрямую (не через `FileAccess`), событие `image` для хоста. В откат картинка не попадает. Модель разговора картинку не видит.
- **`permissions.ts`** — `PermissionGate` (выше), списки особо важных файлов и опасных команд. Запрос `image` (платная картинка) спрашивается всегда и не запоминается; в режиме плана отклоняется.
- **`commandRules.ts`** — что запоминает «Всегда» для команды. `commandRule`: «по началу» (2 слова, для `npm run X` — 3) или точная команда. Точная всегда, если есть синтаксис оболочки (`SHELL_SYNTAX`), программа запускает другую (`RUNS_ANOTHER`, пары `RUNS_ANOTHER_AFTER`), это `curl`/`wget`, одно слово, сразу ключ или кавычки. `ruleMatches` принимает сохранённое правило, только если оно запомнилось бы сегодня.
- **`prompt.ts`** — системная инструкция. Всё, что в ней есть, должно быть стабильным внутри чата.
- **`rules.ts`** — правила: глобальные → `AGENTS.md` → `CLAUDE.md` → `.dimosi/rules.md` → `.dimosi/rules/*.md`. Проектные подключаются только после «Доверять» (решение по хэшу пути и текста).
- **`providers/`** — `anthropic.ts` (Anthropic SDK), `openai.ts` (все OpenAI-совместимые: OpenAI, Polza AI, OpenRouter, DeepSeek, Ollama, custom), `presets.ts` (список сервисов, модели по умолчанию, `checkBaseUrl`), `toolIds.ts` (идентификаторы вызовов, безопасные для любого сервиса). Список моделей (`listModels`) показывает только разговорные: модели для картинок, видео, речи и поиска отсеивает `modelKind` по полям `type` (Polza AI) и `output_modalities` (OpenRouter); запрос к такой модели заканчивается понятной ошибкой `NotChatModelError`. Модели без инструментов (`canCallTools`, поле `supported_parameters` у OpenRouter) в список тоже не попадают. Картинки в ответе модели (`delta.images` у OpenRouter) пока не показываются и не сохраняются: провайдер считает их (`droppedImages`), агент сообщает об этом владельцу.
- **`log.ts`** — журнал: только метаданные, каждая строка проходит маскировку ключей.
- **`update.ts`, `update-key.ts`** — подписанный `latest.json` (Ed25519) и проверка SHA-256 файла.
- **`secrets.ts`** — шифрование файла ключей (AES-256-GCM + scrypt). **`usage.ts`** — токены и стоимость. **`history.ts`** — проверка сохранённой истории.

## 4. Расширение (`packages/vscode`)

- **`src/extension.ts`** — запуск, регистрация команд, выбор сервиса и модели, ключи, правила, отчёт о проблеме.
- **`src/chatView.ts`** — панель чата: ход задачи, вложения, сохранение и восстановление чата, откат.
- **`src/approval.ts`** — карточки подтверждения и окно сравнения. **`src/access.ts`** — строка «Доступ» и окно «Изменить». **`src/commandRules.ts`** — список «Запомненные команды и сайты».
- **`src/editorFiles.ts`** — открытый файл читается из вкладки и правится через `WorkspaceEdit` с сохранением (Cmd+Z отменяет правку агента).
- **`src/problems.ts`** — ошибки редактора после правки. VS Code проверяет только файл во вкладке и молчит о файле без ошибок, поэтому файл открывается фоновой вкладкой (обычной, если у владельца уже есть вкладка предпросмотра) и ожидание ограничено по времени.
- **`src/changes.ts`** — откат; **`src/chatStore.ts`** — `chat.json` (до 20 МБ); **`src/updater.ts`, `vsixInstall.ts`** — самообновление; **`src/ruleTrust.ts`** — окно доверия; **`src/report.ts`, `errorText.ts`** — отчёт и текст ошибок.
- **`src/directFetch.ts`** — запросы к Polza AI (разговор и картинки; только к ней: `directFallbackFor` в `settings.ts`, остальные сервисы ходят через VPN): если запрос через VS Code не ушёл вовсе (`neverConnected`: отказ в соединении, не найден адрес, таймаут соединения), он один раз повторяется напрямую (`__vscodeOriginalFetch`). Обрыв после установки соединения не повторяется: запрос мог дойти и быть оплачен. VS Code запоминает прокси для каждого сайта и перепроверяет его не чаще раза в 5 минут, поэтому после выключения VPN запросы шли бы на уже не работающий адрес. Подключается в `settings.ts` (`buildProvider`).
- **`src/pictures.ts`** — картинка для панели: панель получает сообщение `picture` с путём и сама просит содержимое (`load_picture`); расширение отдаёт `data:`-адрес только настоящей картинке (имя и первые байты, до 8 МБ, путь через `resolvePath`). В `chat.json` хранится только путь.
- **`src/protocol.ts`** — сообщения между расширением и панелью. Не импортирует `vscode`.
- **`webview/`** — интерфейс панели (браузерный код, собирается в `media/chat.js`). **`media/chat.css`** — стили.
- **`package.json`** — команды, настройки (все с `"scope": "application"`), минимальная версия VS Code.

## 6. Рецепты

**Новый инструмент.** `core/src/tools/index.ts`: описание в `TOOL_DEFINITIONS`, исполнитель в `HANDLERS`, подпись в `describe`. Любой путь — через `resolvePath`. Если инструмент что-то меняет или выносит наружу — через `gate.check` (новый вид запроса: `ApprovalRequest` в `permissions.ts`, карточка в `vscode/src/approval.ts` и `webview/cards.ts`, вопрос в `cli/src/index.ts`). Набор инструментов входит в начало запроса: добавление сбросит кэш один раз, это нормально; менять набор по ходу чата нельзя. Обнови перечень в `prompt.ts`, если он там упомянут, и руководство.

**Новая настройка.** `packages/vscode/package.json` (`contributes.configuration`, обязательно `"scope": "application"`) → `vscode/src/settings.ts` (`Settings`, `readSettings`) → передать агенту в `chatView.ts` → для CLI флаг или поле в `cli/src/config.ts` → таблица в разделе 13 руководства → список настроек в `CLAUDE.md`. Тест в настоящем VS Code сверяет значения по умолчанию (`test/real/suite.ts`).

**Новая кнопка панели с командой.** Команда в `package.json` и `extension.ts` (`command(...)`) → имя в `PANEL_COMMANDS` (`chatView.ts`) → кнопка в `webview/`. Тест настоящего VS Code проверяет, что все команды из `package.json` зарегистрированы.

**Новое сообщение между панелью и расширением.** Тип в `protocol.ts` → отправка и обработка с обеих сторон. Если сообщение должно пережить перезагрузку окна — учти его в `Transcript` (`chatStore.ts`).

**Новый сервис нейросети.** `PRESETS` в `providers/presets.ts` и `enum` настройки `dimosi.provider` в `packages/vscode/package.json`. Адрес известного сервиса задаётся только там: ключ не должен уйти на чужой адрес.

**Новая папка, куда командам можно писать** (песочница). `HOME_WRITABLE` в `tools/sandbox.ts` — только кэши, не папки с программами. Тест в `access.test.ts` или `safety.test.ts`, затем ручная проверка на копии проекта в `~` (`npm ci`, сборка, git).

**Поведение редактора** (вкладки, диагностика, сохранение). Сначала измерь в настоящем VS Code (`packages/vscode/test/real/suite.ts`, `npm run test:vscode`), потом повтори в заглушке (`test/e2e/vscode.ts`) и закрепи тестом vitest.

**Найдена ошибка.** Тест, который падает. Если исправление не сейчас — пометь тест `bug(...)` (он зелёный, пока ошибка есть; `AUDIT_STRICT=1` показывает падение) и запиши находку в `AUDIT.md`. После исправления — `it(...)`, строка в таблице «Исправлено», число тестов.

**Новая запись в «Если что-то не работает».** Любой новый текст ошибки, который увидит владелец, — строка в разделе 18 руководства.

## 7. Тесты

- `packages/*/test/**/*.test.ts`, запуск `npm test`. Один файл: `npx vitest run <часть имени>`.
- Код расширения тестируется на заглушке `vscode` (`packages/vscode/test/e2e/vscode.ts`, подключена через alias в `vitest.config.mts`). Заглушка повторяет то, что измерено в настоящем VS Code; управление — объект `stub`.
- Сквозные тесты: `test/e2e/chat.test.ts` (настоящий `ChatViewProvider` + фейковый OpenAI-совместимый сервер `fakeServer.ts`) и `packages/cli/test/cli.test.ts` (собранный CLI, ответы через stdin).
- Настоящий VS Code: `npm run test:vscode` (`test/real/run.mjs` + `suite.ts`; не vitest). Открывает отдельное окно на ~30 с.
- Выпуск: `packages/core/test/release.test.ts` гоняет `scripts/release.mjs` во временной копии с заглушками `npm`, `rsync`, `ssh` и фейковым GitHub.
- Ожидания — только опросом условия (`eventually`, `diesWithin`), без фиксированных пауз.

## 8. Сборка и выпуск

- `npm run build` — esbuild: `packages/vscode/dist/extension.js`, `media/chat.js`, `packages/cli/dist/cli.js`. Адрес обновлений подставляется при сборке из `release.config.json` (секретный файл, не в git); без него самообновление выключено.
- `npm run package` — `dist/dimosi-<версия>.vsix` и `dist/dimosi-cli-<версия>.tgz`.
- `npm run release` (**запускает только владелец**): чистый git → зелёный CI для `HEAD` на GitHub → версия во всех `package.json` → тесты, типы, сборка → ключ подписи (вставляет владелец) → подписанный `latest.json` → заливка (манифест последним) → проверка через публичный адрес → коммит `Release X.Y.Z` и метка.
- Установленные копии проверяют подпись манифеста и SHA-256 файла (`core/src/update.ts`), расширение ставит `.vsix` само (`updater.ts`, `vsixInstall.ts`).
