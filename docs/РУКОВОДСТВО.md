## 1. Что это такое

**dimosi** — помощник-программист внутри VS Code. Вы пишете задачу обычными словами, например «сделай страницу с формой обратной связи». Агент сам читает файлы проекта, создаёт новые, правит существующие и запускает команды.

Агент **не привязан к одной компании**. Вы сами выбираете сервис и платите ему напрямую по своему API-ключу:

| Сервис | Что это |
|---|---|
| **Anthropic** | Модели Claude напрямую от разработчика |
| **OpenAI** | Модели GPT напрямую от разработчика |
| **Polza AI** | Российский агрегатор: Claude, GPT, DeepSeek и сотни других моделей, оплата в рублях |
| **OpenRouter** | Международный агрегатор моделей |
| **DeepSeek** | Модели DeepSeek |
| **Ollama** | Бесплатная нейросеть, которая работает на вашем компьютере |
| **Custom** | Любой другой сервис, совместимый с OpenAI API |

Комплект состоит из двух файлов в папке `dist` проекта:
- **`dimosi-<версия>.vsix`** (сейчас `dimosi-0.4.4.vsix`) — расширение для VS Code. Это основной способ работы.
- **`dimosi-cli-<версия>.tgz`** (сейчас `dimosi-cli-0.4.4.tgz`) — версия для терминала. Нужна, только если хотите работать в окне терминала.

## 2. Что понадобится

1. **VS Code версии 1.140 или новее.** Проверить: меню **Code → About Visual Studio Code** (Windows: **Help → About**). Обновить: **Code → Check for Updates…**
2. **API-ключ** хотя бы одного сервиса ([раздел 6](#6-где-взять-api-ключ)). Для Ollama ключ не нужен.
3. **Интернет** (кроме Ollama).

## 3. Переход со старой версии (API AI Agent)

Если у вас стояла первая версия под названием **API AI Agent**, сделайте следующее. Новая версия — отдельное расширение, поэтому ключ нужно перенести.

1. **Сохраните ключи из старой версии** (если не помните ключ наизусть):
   1. `Cmd+Shift+P` → наберите **API AI: Экспортировать ключи в файл…** → Enter.
   2. Придумайте пароль и повторите его.
   3. Сохраните файл, например на Рабочий стол.
2. **Удалите старую версию:** панель **Extensions** (`Cmd+Shift+X`) → найдите **API AI Agent** → значок шестерёнки → **Uninstall**.
3. **Установите dimosi** ([раздел 4](#4-установка)).
4. **Загрузите ключи:** `Cmd+Shift+P` → **dimosi: Импортировать ключи из файла…** → выберите файл → введите пароль. Старый файл подходит, конвертировать его не нужно.
   - Можно и проще: ввести ключ Polza AI заново ([раздел 5](#5-первый-запуск-сервис-ключ-модель)).

## 4. Установка

1. Откройте VS Code.
2. Нажмите `Cmd+Shift+X` (Windows: `Ctrl+Shift+X`) — откроется панель расширений.
3. Вверху панели нажмите **«…»** (три точки) → **Install from VSIX…**
4. Выберите файл `dimosi-<версия>.vsix` с самым большим номером версии (в папке `dist` проекта). На Mac удобно так: в окне выбора нажмите `Cmd+Shift+G`, вставьте путь к папке и нажмите Enter.
5. Дождитесь сообщения об установке. Если VS Code предложит перезагрузить окно, согласитесь.

На левой вертикальной панели появится **ваш логотип** — это панель dimosi.

> Устанавливать вручную нужно только один раз: дальше dimosi обновляется сам ([раздел 14а](#14а-обновления)).

## 5. Первый запуск: сервис, ключ, модель

1. **Откройте папку проекта:** **File → Open Folder…** (Файл → Открыть папку). Подойдёт и пустая папка. Для первого знакомства лучше взять отдельную тестовую папку.
2. **Откройте панель dimosi:** нажмите логотип на левой панели.
3. **Подключите нейросеть.** Если ключей ещё нет, на экране приветствия будет кнопка **«Выбрать сервис и ввести ключ»**. Нажмите её:
   1. выберите сервис, например **Polza AI**;
   2. вставьте API-ключ (`Cmd+V`) и нажмите **Enter** — вместо символов будут точки, так и задумано;
   3. выберите модель из списка (можно начать печатать для поиска). Пометка **«рекомендуется»** — хороший выбор по умолчанию.
4. Вверху панели появятся название сервиса и модели. Готово.

**Попробуйте:** нажмите на один из примеров на экране приветствия или напишите свою задачу и нажмите **Enter**.

## 6. Где взять API-ключ

API-ключ — длинная строка вроде `sk-...`. Она подтверждает, что запросы идут от вас, а сервис списывает деньги с вашего баланса. Обращайтесь с ключом как с паролем от кошелька.

| Сервис | Где получить ключ | Оплата |
|---|---|---|
| **Polza AI** | [polza.ai](https://polza.ai) → личный кабинет → **API-ключи** ([прямая ссылка](https://polza.ai/dashboard/api-keys)) | В рублях, в личном кабинете |
| **Anthropic** | [console.anthropic.com](https://console.anthropic.com) → **API Keys** → **Create Key** | Раздел **Billing** |
| **OpenAI** | [platform.openai.com/api-keys](https://platform.openai.com/api-keys) | Раздел **Billing** |
| **OpenRouter** | [openrouter.ai/keys](https://openrouter.ai/keys) | Раздел **Credits** |
| **DeepSeek** | [platform.deepseek.com](https://platform.deepseek.com) → **API keys** | Раздел **Top up** |
| **Ollama** | Ключ не нужен | Бесплатно |

**Совет:** через **Polza AI** доступны и Claude, и GPT, и DeepSeek с оплатой в рублях. Модели называются так: `anthropic/claude-opus-5.5`, `openai/gpt-6.1-sol`, `deepseek/deepseek-v4-flash`.

## 7. Как работать с агентом

Пишите задачу так, как объясняли бы живому программисту. Чем конкретнее, тем лучше:

- «Расскажи, что делает этот проект и как его запустить».
- «Добавь на страницу contacts.html форму: имя, телефон, сообщение».
- «При запуске `npm start` появляется ошибка — найди причину и исправь».

Агент помнит весь разговор, поэтому можно уточнять: «теперь сделай кнопку синей».

**Элементы панели:**

| Элемент | Что делает |
|---|---|
| Логотип и «Сервис / модель» вверху | Нажмите на название модели, чтобы сменить сервис или модель |
| Плашка **«С подтверждением»** | Включает и выключает подтверждения ([раздел 8](#8-подтверждения-и-откат-изменений)) |
| Строка **«Доступ: проект»** и ссылка **«Изменить»** | Показывает, какие папки видит агент. «Изменить» открывает агенту папки вне проекта или закрывает их ([раздел 7б](#7б-папки-вне-проекта)) |
| **+** в заголовке панели | Новый чат: агент начинает с чистого листа, а прежний чат уходит в «Прошлые чаты» |
| **Часы** в заголовке | Прошлые чаты этой папки: открыть или удалить ([раздел 7а](#7а-чат-сохраняется-сам)) |
| **Книга** в заголовке | Правила для агента ([раздел 9](#9-правила-для-агента)) |
| **Сервер** в заголовке | Выбрать сервис и модель |
| **Ключ** в заголовке | Ввести или заменить API-ключ |
| **Скрепка** под полем ввода | Прикрепить файлы и картинки |
| Кнопка **«Сначала план»** под полем ввода | Агент сначала изучает задачу и показывает план, ничего не меняя ([раздел 7в](#7в-режим-сначала-план)) |
| **Стоп** (во время работы) | Немедленно остановить агента. Что он успел написать, агент помнит: на «продолжай» он пойдёт дальше, а не начнёт заново |

Строки с иконками в чате — это действия агента: чтение файла, поиск, команда. Зелёная точка справа — успешно, красная — ошибка. Нажмите на стрелку под строкой, чтобы увидеть подробности.

Кнопка **«Копировать»** появляется при наведении на блок кода в ответе.

**Агент видит ошибки редактора.** После каждой правки файла dimosi передаёт агенту ошибки, которые VS Code подчёркивает в этом файле красным (вкладка **Problems**). Агент сразу узнаёт, что сломал, и обычно исправляет сам, без запуска сборки. Как это устроено:

- передаются только ошибки (красные), предупреждения (жёлтые) не передаются; не больше 10 на файл;
- VS Code проверяет только файлы, открытые во вкладке. Поэтому на время проверки dimosi открывает изменённый файл во вкладке **в фоне**: ваша вкладка остаётся впереди, курсор никуда не уходит. После проверки эта вкладка закрывается сама. Ваши вкладки остаются на месте, в том числе открытая одним щелчком (с названием курсивом). Если у вас не было открыто ни одного файла, изменённый файл остаётся на экране;
- ошибки появляются не мгновенно, поэтому после правки dimosi ждёт ответа VS Code: обычно от полусекунды до полутора секунд на файл, самое большее 4 секунды. Кнопка **Стоп** прерывает ожидание сразу;
- если для языка файла в VS Code нет проверки (обычный текст, Markdown), ждать нечего: после пары правок dimosi перестаёт открывать вкладку и ждать для таких файлов;
- ошибки видны в строке действия: нажмите стрелку под «Правка …» или «Запись …»;
- в терминальной версии этого нет: там нет редактора.

### 7а. Чат сохраняется сам

dimosi запоминает **последний чат в каждой папке**. Если окно перезагрузилось (например, после обновления dimosi или команды **Developer: Reload Window**) или вы закрыли и снова открыли VS Code:

1. откройте ту же папку проекта;
2. нажмите логотип dimosi на левой панели.

Чат появится таким же, каким был: ваши сообщения, ответы, план, карточки «Изменено файлов» с кнопками **Откатить**. Агент помнит разговор, можно сразу писать дальше.

- Если окно перезагрузилось **посреди задачи**, внизу чата будет надпись «Задача прервалась…». Напишите «продолжай», и агент продолжит. Вопрос, который висел без ответа, считается отклонённым.
- Кнопка **+** («Новый чат») начинает разговор заново. Прежний чат не стирается, а уходит в **прошлые чаты** (см. ниже). Чат, в котором вы ничего не написали, не сохраняется.
- На один чат отводится до 20 МБ. Если чат больше (много картинок или правок огромных файлов), dimosi сначала не сохраняет картинки, а потом исходные версии файлов. У таких файлов вместо кнопки **Откатить** будет серая надпись **«откат недоступен»**: после перезагрузки их уже нельзя вернуть кнопкой (воспользуйтесь git). Созданные агентом файлы откатить можно всегда.
- Если файл сохранения повреждён, dimosi просто откроет пустой чат.

**Прошлые чаты.** dimosi хранит до 30 прошлых чатов каждой папки. Чтобы вернуться к одному из них:

1. нажмите значок **часов** в заголовке панели (или `Cmd+Shift+P` → **dimosi: Прошлые чаты…**);
2. появится список: первая строка каждого чата — ваше первое сообщение в нём, рядом дата и число сообщений. В списке можно искать, просто начав печатать;
3. выберите чат, затем **Открыть**. Чат появится в панели таким, каким был, вместе с карточками отката. Агент помнит разговор, можно писать дальше.

- Чат, который был открыт до этого, сам уходит в прошлые: ничего не теряется.
- Чтобы удалить чат, выберите его в списке, затем **Удалить** и подтвердите. Вернуть удалённый чат нельзя.
- Когда чатов становится больше 30, самые старые удаляются сами.
- Пока агент работает над задачей, другой чат не открывается: дождитесь окончания или нажмите **Стоп**.
- У каждой папки проекта свой список чатов.

Чаты хранятся в служебной папке VS Code на вашем компьютере и никуда не отправляются.

### 7б. Папки вне проекта

Обычно агент видит только папку проекта, открытую в VS Code. Если ему нужны файлы из другого места (заметки, соседний проект, общая библиотека), откройте ему эту папку.

**Как открыть папку:**

1. Под названием модели в панели чата есть строка **«Доступ: проект»**. Нажмите рядом **«Изменить»**.
2. Вверху окна появится список. Выберите **«Открыть агенту ещё одну папку…»**.
3. В окне выбора укажите папку и нажмите **«Открыть агенту»**.
4. Выберите, что агенту можно:
   - **Только чтение**: агент читает файлы и ищет по ним, но ничего не меняет. Команды агента тоже не смогут там ничего записать. Берите этот вариант, если не уверены.
   - **Чтение и запись**: агент может менять файлы. Подтверждения и откат работают так же, как в проекте.
5. Строка в панели изменится на **«Доступ: проект + 1 папка»**. Наведите на неё мышь, чтобы увидеть список папок.

Список снова появится на экране: можно добавить ещё папку или закрыть его клавишей **Esc**.

**Как поменять или убрать:** **«Изменить»** → нажмите на папку в списке → **«Разрешить запись»** (или **«Оставить только чтение»**) либо **«Убрать из списка»**. Сама папка и файлы в ней при этом не меняются.

**Что важно знать:**

- Список общий для всех проектов и хранится в ваших личных настройках VS Code (настройка **Extra Folders**). Чужой проект добавить в него папку не может.
- В начале работы dimosi ничего не спрашивает: что открыто, видно в строке «Доступ».
- Изменение списка действует со следующего сообщения агенту. Новый чат начинать не нужно.
- Файлы из этих папок агент называет полным путём, например `/Users/вы/notes/план.md`. Так же они показаны в карточках подтверждения и отката.
- Нельзя открыть всю домашнюю папку или весь диск: нужна конкретная папка. Нельзя открыть папки с ключами и данными программ (`~/.ssh`, `~/.config`, `~/Library/…`, iCloud Drive, настройки dimosi и другие из [раздела 17](#17-безопасность)).
- Папку внутри «Документов», «Рабочего стола», «Загрузок» открыть можно. Откроется только она, соседние папки останутся закрытыми. Сами «Документы», «Рабочий стол», «Загрузки» и `~/Library` целиком открыть нельзя: dimosi ответит «слишком широко» и попросит выбрать папку внутри.
- Файлы с паролями (`.env`, ключи и другие из [раздела 17](#17-безопасность)) закрыты и в этих папках.
- Содержимое прочитанных файлов уходит сервису ИИ, как и файлы проекта. Не открывайте папки с личными документами без нужды.
- Если папка в списке есть, но её удалили или отключили диск, в строке будет «не подключено: 1». Наведите мышь на строку, чтобы увидеть причину.

### 7в. Режим «Сначала план»

Для большой или рискованной задачи удобно сначала увидеть, что агент собирается делать, и только потом разрешить ему работать.

1. Нажмите кнопку **«Сначала план»** под полем ввода. Она зальётся синим, надпись сменится на **«✓ План включён»**, а кнопка отправки станет называться **«Составить план»**: режим включён. Выключенная кнопка серая, с рамкой и надписью «Сначала план».
2. Напишите задачу и отправьте.
3. Агент читает файлы и ищет по проекту, затем показывает план по шагам и коротко объясняет его. **Файлы он не меняет и команды не запускает**, вопросов с подтверждениями в это время нет.
4. Под ответом появится карточка **«План готов. Агент пока ничего не менял»**. Дальше два пути:
   - план устраивает: нажмите **«Выполнить план»**. Режим выключится сам, агент начнёт работу, подтверждения пойдут как обычно;
   - план нужно поправить: напишите, что изменить. Режим остаётся включённым, агент покажет новый план.

Что ещё важно:

- В режиме плана не выполняется ни одна команда, даже те, что вы раньше разрешили кнопкой «Всегда» (`git status`, `npm test`): dimosi не может отличить команду, которая только смотрит, от команды, которая меняет. Агент разбирается чтением файлов и поиском, а команды и правки откладывает до «Выполнить план». Читать страницы из интернета в режиме плана можно, с обычным вопросом про сайт.
- Режим действует, пока вы его не выключите: кнопкой **«Выполнить план»** или повторным нажатием **«Сначала план»**. После перезапуска VS Code он выключен.
- Режим «Без подтверждений» запрет не снимает: пока включён «Сначала план», агент ничего не меняет.
- В строках действий агента в это время может встретиться красная точка с текстом «Plan mode is on»: это агент попробовал что-то изменить, а dimosi его остановил.

### 7г. Чтение страниц из интернета

Агент может прочитать страницу в интернете: документацию библиотеки, статью, описание API. Попросите его прямо («прочитай https://… и сделай так же») или он предложит сам.

1. В чате появится карточка **«Прочитать страницу в интернете»** с полным адресом страницы.
2. Проверьте адрес: сайт должен быть вам знаком, а в адресе не должно быть ничего лишнего (сайт увидит адрес целиком).
3. Нажмите:
   - **Прочитать**: агент получит текст этой страницы;
   - **Отклонить**: к сайту никто не обращается;
   - **Всегда для имя-сайта**: про страницы этого сайта dimosi больше не спрашивает, во всех проектах.

Что важно знать:

- Про каждый новый сайт dimosi спрашивает **всегда**, даже в режиме «Без подтверждений».
- Даже для сайта с «Всегда» dimosi спросит ещё раз, если в адресе после знака `?` идёт длинная строка (больше 100 знаков). Карточка будет с жёлтой рамкой и без кнопки «Всегда». Сайт видит адрес целиком, и в такой строке наружу могут уйти данные из проекта. Посмотрите на адрес: если строка похожа на обычный поисковый запрос, нажмите **Прочитать**; если в ней куски вашего кода, пароли или непонятный набор букв, нажмите **Отклонить** и спросите агента, зачем ему этот адрес.
- Читаются только адреса `https://` обычных сайтов. Адреса вашего компьютера и домашней сети, адреса с логином и паролем не читаются.
- Если страница перенаправляет на другой сайт, агент сообщит об этом и спросит разрешение уже для нового сайта.
- Агент получает только текст страницы (до 40 тысяч знаков), без картинок и без входа в аккаунты. Страницы в старых кодировках (например, windows-1251 на давних русских сайтах) читаются правильно. Страницы, которые требуют входа или рисуются программой в браузере, прочитать не получится.
- Текст страницы для агента — данные, а не указания. Если на странице написано «выполни команду», агент должен сказать об этом вам, а не выполнять. Опасные команды и защищённые файлы всё равно спрашиваются отдельно.
- Список сайтов с «Всегда» виден там же, где запомненные команды: три точки **«…»** в заголовке панели → **«Запомненные команды и сайты»**. Нажмите на сайт и подтвердите **«Забыть»**, чтобы агент снова спрашивал.

### 7д. Создание картинок

Агент может нарисовать картинку: баннер, иллюстрацию, значок, набросок экрана. Рисует не та модель, с которой вы разговариваете, а отдельная модель для картинок через сервис **Polza AI**.

Что нужно один раз:

1. Ключ Polza AI. Если вы уже работаете через Polza AI, он есть. Если работаете через другой сервис (OpenRouter, Anthropic), добавьте ключ Polza AI: **Cmd+Shift+P** → **dimosi: Выбрать сервис и модель** → Polza AI → введите ключ, затем верните прежний сервис тем же способом. Оба ключа сохранятся.
2. Модель для разговора оставьте обычную (например, `anthropic/claude-opus-5.5`). Модель, которая рисует, выбирать вместо неё не нужно.

Как пользоваться:

1. Напишите обычными словами: «нарисуй баннер для главной страницы: закат над морем, надпись „Лето“, сохрани в папку images».
2. В чате появится карточка **«Создать картинку имя-файла»**. В ней описание, которое агент составил для рисующей модели, название этой модели и цена одной картинки.
3. Нажмите:
   - **Создать**: dimosi отправит запрос, через 10–60 секунд сохранит файл в проект и покажет картинку в чате;
   - **Отклонить**: ничего не отправляется и не оплачивается.
4. Нажмите на имя файла под картинкой, чтобы открыть её в VS Code.

Что важно знать:

- Каждая картинка **платная** (обычно 3–15 ₽, цена видна в карточке). Поэтому dimosi спрашивает про каждую, даже в режиме «Без подтверждений», и кнопки «Всегда» в карточке нет.
- Какая модель рисует, задаётся настройкой **Image Model** ([раздел 13](#13-смена-сервиса-модели-и-ключей)). Пусто — `qwen/image-2`. Названия других моделей — на сайте polza.ai в разделе моделей для изображений.
- Картинка всегда сохраняется новым файлом (`.png`, `.jpg` или `.webp`). Существующий файл агент картинкой не заменит: он выберет другое имя ещё до вопроса. Окончание файла может отличаться от названного в карточке: сервис сам решает, в каком формате рисовать (часто `.jpg`). Если имя заняли, пока картинка рисовалась, она сохранится рядом с добавкой `-2`: оплаченная картинка не пропадает.
- Кнопка **«Откатить»** на картинки не действует: ненужный файл удалите сами.
- Сам агент картинку не видит. Если нужно, чтобы он её оценил, прикрепите файл к следующему сообщению ([раздел 10](#10-вложения-файлы-и-картинки)).
- Описание картинки уходит сервису Polza AI. Не просите рисовать то, что содержит пароли или личные данные.
- В режиме «Сначала план» картинки не создаются.
- Цена в карточке — подсказка из списка моделей Polza AI. Если сервис не ответил за 10 секунд, карточка появится без цены; на саму картинку это не влияет.
- Если нажать **Стоп** после кнопки «Создать», картинка может быть уже оплачена, но не сохранена: запрос к этому моменту ушёл.
- Картинка больше 30 МБ не сохраняется.
- В терминальной версии ([раздел 15](#15-работа-из-терминала-необязательно)) картинки создаются, только пока выбран сервис Polza AI, и всегда моделью `qwen/image-2`: настройки **Image Model** там нет.
- Видео, музыку и озвучку dimosi пока не создаёт.

### 7е. Усердие модели

«Усердие» — насколько старательно модель работает над ответом. Низкое — быстрее и дешевле, годится для простых правок. Высокое и наибольшее — модель дольше думает и тратит больше, зато лучше справляется с трудными задачами.

**По умолчанию настройка выключена:** dimosi ничего не передаёт, модель решает сама — так он работал всегда.

Как включить:

1. `Cmd+Shift+P` → **dimosi: Усердие модели…**
2. Выберите уровень: **Низкое**, **Среднее**, **Высокое** или **Наибольшее**. Чтобы выключить — **Как решит модель**.
3. Вверху панели чата, рядом с названием модели, появится кнопка **«Усердие: высокое»**. Нажатие на неё открывает тот же список.

Что важно знать:

- Настройка действует с сервисами **Anthropic, Polza AI, OpenRouter и OpenAI**. С остальными (DeepSeek, Ollama, свой сервер) она ничего не меняет: dimosi один раз за чат напишет об этом, и работа продолжится.
- **Через Polza AI для моделей Claude настройка включает «размышления»**: модель сначала обдумывает задачу про себя. Размышления оплачиваются как текст ответа, поэтому здесь любой уровень, даже «Низкое», может стоить дороже, чем выключенная настройка. Экономию даёт только Anthropic напрямую.
- Если сервис или модель настройку не принимают, dimosi получает ответ без неё и один раз за чат пишет об этом. Работа не прерывается.
- Менять уровень лучше между чатами: смена посреди чата может один раз сбросить кэш ([раздел 12](#12-ход-работы-и-стоимость)).
- Как проверить, что настройка действует: сравните в строке внизу панели, сколько модель написала (второе число токенов) и сколько стоил похожий запрос с настройкой и без неё.

## 8. Подтверждения и откат изменений

### Подтверждения прямо в чате

По умолчанию агент **ничего не меняет без вашего разрешения.**

**Изменение файла.** В чате появляется карточка, выделенная синей рамкой:
- название файла и счётчик строк: `+3 −1`;
- изменения построчно: **зелёным** — добавленное, **красным** — удалённое, слева номера строк;
- кнопки:
  - **Применить** — сохранить изменение;
  - **Отклонить** — не сохранять (агент узнает об отказе и спросит, как поступить);
  - **Всегда** — больше не спрашивать про файлы до нового чата (после **+** или перезапуска VS Code агент снова спросит);
  - **Открыть сравнение** — показать старую и новую версии рядом в большом окне.

**Команда** (например, установка библиотеки или запуск тестов). Карточка с текстом команды и кнопками **Выполнить / Отклонить / Всегда для…**. Если не понимаете, что делает команда, нажмите **Отклонить** и спросите агента в чате.

**Кнопка «Всегда» у команды** запоминает разрешение для этого проекта. Оно действует и в новых чатах, и после перезапуска VS Code. Что именно запомнится, написано на самой кнопке:

- **«Всегда для «npm test …»»** — агент больше не спрашивает про команды, которые **начинаются** с этих слов: `npm test`, `npm test -- --watch` и так далее. Про `npm install` он по-прежнему спросит.
- **«Всегда для этой команды»** — запоминается только команда целиком, буква в букву. Так бывает, когда по началу команды нельзя понять, что она сделает: в ней несколько команд подряд (`&&`, `;`, `|`), одно слово (`ls`), сразу идёт ключ (`node -e …`) или это программа, которая запускает другую (`bash`, `env`, `xargs`, а также пары слов вроде `npm exec`, `pnpm dlx`, `docker run`, `uv run`). Так же целиком запоминаются `curl` и `wget`: про каждый новый адрес агент спросит.

Команда из нескольких частей никогда не проходит «по началу»: после разрешения на `npm test` про `npm test && rm -rf папка` агент спросит. Опасные команды (ниже) спрашиваются всегда, запомнить их нельзя.

**Посмотреть и убрать запомненное:** три точки **«…»** в заголовке панели dimosi → **«dimosi: Запомненные команды и сайты («Всегда»)…»**. То же самое открывает ссылка **«Запомненные команды»**, которая появляется на карточке после нажатия «Всегда». В списке нажмите на команду и подтвердите **«Забыть»**: агент снова будет про неё спрашивать. **«Забыть все»** очищает список проекта.

Список хранится в VS Code отдельно для каждого проекта, а не в папке проекта: чужой проект не может принести свои разрешения.

**Если файл открыт в редакторе**, агент работает с тем, что вы видите на экране, даже если вы ещё не сохранили свои правки:
- агент читает текст прямо из вкладки, со всеми несохранёнными изменениями, и правит именно его;
- после **Применить** изменение появляется во вкладке, и файл сохраняется (вместе с вашими несохранёнными правками);
- **Cmd+Z** (Windows: **Ctrl+Z**) во вкладке отменяет правку агента, как обычную. Нажмите ещё раз, чтобы отменить и свои правки;
- окна «файл изменён на диске» больше не будет.

Файлы, которые не открыты, агент правит прямо на диске. Терминальная версия всегда работает с диском.

**Скрытые символы.** Иногда в тексте бывают невидимые знаки или знаки, меняющие направление письма: ими можно сделать так, чтобы команда на экране выглядела безобидно, а делала другое. dimosi показывает каждый такой знак меткой вроде `⟦U+202E⟧`, а карточка получает жёлтую рамку и предупреждение «Внимание: скрытые символы». Кнопки **Всегда** на ней нет. Если не знаете, откуда они взялись, нажмите **Отклонить** и спросите агента. Длинные строки изменения в карточке переносятся, поэтому всё изменение видно без прокрутки вбок.

Если команда работает слишком долго (по умолчанию дольше 2 минут) или вы нажали **Стоп**, dimosi останавливает её вместе со всеми процессами, которые она запустила.

Пока карточка ждёт ответа, внизу панели написано «Ждёт вашего решения…». Если панель была свёрнута, она откроется сама.

### Откат: вернуть как было

После каждой задачи, в которой агент менял файлы, появляется карточка **«Изменено файлов: N»**:
- нажмите на имя файла, чтобы открыть его;
- **Откатить** рядом с файлом — вернуть версию до этой задачи (созданный агентом файл будет удалён);
- **Откатить все** — отменить все изменения этой задачи.

Если вы сами успели поправить файл после агента (даже не сохраняя), dimosi сначала спросит, точно ли откатывать: ваши правки в этом файле пропадут. Откат открытого файла тоже можно отменить через **Cmd+Z** во вкладке.

> Карточки отката принадлежат своему чату. После **нового чата** (+) они уходят вместе с ним в прошлые чаты: откройте тот чат снова, и кнопки «Откатить» вернутся ([раздел 7а](#7а-чат-сохраняется-сам)). Перезагрузка окна и перезапуск VS Code откат тоже не отменяют. Для серьёзных проектов дополнительно используйте git.

### Особо важные файлы: всегда с отдельным вопросом

Некоторые файлы могут **сами запускать команды позже**, без участия агента:
- всё в папке `.vscode/` (например, `tasks.json` может выполнить команду при открытии папки);
- сценарии GitHub Actions в `.github/workflows/` (выполняются на серверах GitHub);
- любой `package.json` (скрипты вроде `postinstall` выполняются при `npm install`);
- git-хуки Husky (`.husky/`), `.envrc` (его выполняет программа direnv), настройки Dev Container (`.devcontainer/`), файлы рабочей области `*.code-workspace`;
- правила для агента: всё в папке `.dimosi/`, а также `AGENTS.md` и `CLAUDE.md`. Их текст становится указаниями агенту в следующих задачах, поэтому агент не может переписать их молча.

Изменение такого файла dimosi **всегда** показывает отдельной карточкой с жёлтой рамкой и предупреждением. То же действует в папках вне проекта, открытых для записи ([раздел 7б](#7б-папки-вне-проекта)): там эти файлы ищутся внутри открытой папки. Так будет даже в режиме «Без подтверждений» и даже если раньше вы нажали **Всегда**. Кнопки **Всегда** на такой карточке нет. Применяйте, только если понимаете изменение.

### Опасные команды: тоже всегда с отдельным вопросом

Откат dimosi возвращает только **правки файлов**. Если команда удалила файлы или стёрла изменения в git, откат их не вернёт. Поэтому такие команды dimosi **всегда** показывает карточкой с жёлтой рамкой и пояснением, что именно опасно:
- удаление файлов: `rm -r`, `rm -f`, `find … -delete`;
- права администратора: `sudo`;
- git, который стирает изменения или ветки: `git reset --hard`, `git clean`, `git checkout -- …`, `git restore`, `git branch -D`, `git stash drop`;
- отправка кода и пакетов в интернет: `git push`, `npm publish`;
- отправка данных и файлов наружу: `curl -d`, `curl -F`, `curl -T`, `wget --post-file`, `scp`, `rsync` на другой компьютер, `nc`;
- любая команда, где упомянут файл с секретами: `.env`, `*.pem`, `secrets.json` и другие из [раздела 17](#17-безопасность). Например, `cat .env`: вывод команды уходит сервису ИИ;
- скачать и сразу выполнить: `curl … | sh`;
- Связка ключей (`security find-…`), управление программами (`osascript`), закрытие программ (`killall`, `pkill`), выключение компьютера и стирание диска.

Так будет даже в режиме «Без подтверждений» и после **Всегда**, а кнопки **Всегда** на такой карточке нет. Если не понимаете, зачем агенту эта команда, нажмите **Отклонить** и спросите его в чате.

Список ловит случайные ошибки, но обойти его можно. Главная защита от вредной команды — песочница ([раздел 17](#17-безопасность)).

### Режим без подтверждений

Нажмите плашку **«С подтверждением»** вверху и подтвердите. Плашка станет красной: **«Без подтверждений»**, и агент будет действовать сам. Включайте этот режим только в тех папках, которые не жалко. Повторное нажатие возвращает подтверждения.

## 9. Правила для агента

Правила — ваши постоянные указания: на каком языке отвечать, какой стиль кода использовать, что нельзя трогать. **Агент перечитывает их перед каждым ответом**, поэтому изменения действуют сразу, без нового чата.

### Два вида правил

| Вид | Где лежит | Для чего |
|---|---|---|
| **Глобальные** | `~/.config/dimosi/rules.md` (Windows: `%APPDATA%\dimosi\rules.md`) | Ваши общие привычки — для всех проектов |
| **Правила проекта** | В папке проекта: `.dimosi/rules.md`, файлы в `.dimosi/rules/`, а также `AGENTS.md` и `CLAUDE.md` | Особенности конкретного проекта |

При конфликте приоритет у правил проекта.

### Как работают глобальные правила

Глобальные правила — это один файл с вашими привычками, которые действуют **во всех проектах**: и в VS Code, и в терминальной версии.

- **Где лежит.** На Mac: `~/.config/dimosi/rules.md` (папка `.config` в вашей домашней папке, в Finder она скрыта). На Windows: `%APPDATA%\dimosi\rules.md`. Открыть проще всего так: значок **книги** вверху панели → **Открыть глобальные правила**. Если файла ещё нет, dimosi создаст его с примером.
- **Когда читается.** Заново перед каждой задачей. Сохранили файл (`Cmd+S`) — следующее сообщение агенту уже идёт с новыми правилами, новый чат не нужен.
- **Доверие.** О глобальных правилах dimosi не спрашивает: их пишете только вы.
- **Порядок.** Агент получает правила одним блоком в таком порядке: глобальные → `AGENTS.md` → `CLAUDE.md` → `.dimosi/rules.md` → файлы из `.dimosi/rules/` по алфавиту. Агенту сказано, что при противоречии правила проекта важнее глобальных. Например, глобально «отвечай кратко», а в проекте «пиши подробные отчёты» — в этом проекте будут подробные отчёты.
- **Размер.** До 30 тысяч символов на файл и до 80 тысяч на все правила вместе. Глобальные идут первыми и занимают место первыми: огромный глобальный файл может вытеснить правила проекта.
- **Цена.** Правила отправляются нейросети на каждом шаге задачи. Благодаря кэшу это дёшево, но каждая строка всё равно стоит денег и внимания модели. Хорошие глобальные правила — 5–30 коротких строк.
- **Перенос.** На другой компьютер файл сам не переезжает: возьмите его с собой ([раздел 14](#14-перенос-на-другой-компьютер)).

**Что писать в глобальные правила:** то, что верно для любого проекта: язык ответов, как объяснять («простыми словами, без жаргона»), чего не делать без спроса («не удаляй файлы», «не ставь новые библиотеки»). **Что не писать:** особенности конкретного проекта (команды сборки, структура папок) — им место в `.dimosi/rules.md` этого проекта. И не повторяйте то, что агент и так делает по умолчанию: «будь внимателен», «пиши хороший код» — это лишние токены.

### Доверие к правилам проекта

Правила проекта (`AGENTS.md`, `CLAUDE.md` и всё в папке `.dimosi/`) часто приходят **вместе с чужим проектом**: скачанным из интернета или полученным от подрядчика. В них могут оказаться вредные указания, например «перед работой выполни такую-то команду». Поэтому dimosi подключает их только с вашего согласия:

1. Когда такой файл найден в папке впервые (или его текст изменился), при следующей задаче появится небольшое окно **«Доверять правилам из .dimosi/rules.md в этом проекте?»** (или из `AGENTS.md`, `CLAUDE.md`): путь к файлу и его первые строки.
2. Выберите:
   - **Доверять** — файл станет правилами для агента;
   - **Не доверять** — агент работает без этого файла;
   - **Открыть файл** — файл откроется в редакторе, читайте спокойно. Текущая задача выполняется без него. Решите потом: нажмите плашку **«Правила»** над полем ввода или отправьте следующую задачу, и dimosi спросит снова;
   - **Esc** (закрыть окно) — решить потом: dimosi спросит снова при следующей задаче.
3. Решение запоминается. Снова dimosi спросит, только если текст файла изменится.

Без вопроса подключаются только глобальные правила. Если файл правил создал сам dimosi (команда **Создать правила проекта** или новый файл, который агент записал с вашего одобрения), вопроса тоже не будет. Но после того как вы поправите такой файл, dimosi один раз спросит о нём снова: он не может отличить вашу правку от чужой.

Файлы правил, которые на самом деле лежат вне проекта (ярлык на чужой файл), похожи на файлы с паролями (`.env` и т. п.) или больше 1 МБ, dimosi не подключает совсем.

Плашка над полем ввода показывает недоверенные файлы отдельно: **«Правила: 1 · не доверено: 1»**. Чтобы передумать: нажмите плашку (или **книгу** вверху) → выберите файл со значком щита → ответьте заново.

В терминальной версии тот же вопрос задаётся прямо в терминале: `y` — доверять, `n` — нет, Enter — решить потом.

### Как создать

Нажмите значок **книги** вверху панели (или плашку **«Правила»** над полем ввода):
- **Открыть глобальные правила** — откроется файл с готовым шаблоном. Впишите свои правила, по одному на строку, и сохраните (`Cmd+S`).
- **Создать правила проекта** — создаст `.dimosi/rules.md` с разделами «О проекте», «Стиль кода», «Запреты», «Команды». Заполните их.
- **Сгенерировать правила по проекту** — агент сам изучит проект и напишет правила. Запись файла вы подтвердите как обычно. Потом проверьте и поправьте текст.

Над полем ввода всегда видна плашка **«Правила: N»** — сколько файлов правил действует сейчас. Наведите на неё, чтобы увидеть список. «Без правил» значит, что правил пока нет.

**Пример глобальных правил:**
```
- Отвечай на русском языке.
- Перед изменениями кратко объясняй план.
- Комментарии в коде пиши по-русски.
- Не удаляй файлы без явной просьбы.
```

> Правила не должны быть огромными: учитывается до 30 тысяч символов на файл и до 80 тысяч всего. Если файл больше, в списке правил он отмечен «обрезано».

## 10. Вложения: файлы и картинки

К сообщению можно приложить файлы и картинки. Вложения появляются плашками над полем ввода, а **×** на плашке убирает вложение.

| Способ | Как |
|---|---|
| **Скрепка** | Кнопка под полем ввода → выберите один или несколько файлов |
| **@** | Наберите `@` и начало имени файла → выберите из списка стрелками и Enter (или мышкой) |
| **Открытый файл** | Над полем ввода есть пунктирная плашка с именем открытого файла — нажмите её |
| **Скриншот** | Скопируйте картинку (например, `Cmd+Ctrl+Shift+4` на Mac) и вставьте в поле ввода `Cmd+V` |
| **Перетаскивание** | Картинки перетаскиваются откуда угодно. Файлы из списка VS Code — с зажатым **Shift** |

Ограничения: текстовые файлы до 100 тысяч символов (больше — обрезаются), картинки PNG, JPG, GIF, WebP до 5 МБ.

**Файлы с паролями не прикрепляются.** `.env` и другие файлы из [раздела 17](#17-безопасность) (и ярлыки на них) нельзя приложить ни скрепкой, ни через `@`, ни выделением в редакторе: dimosi покажет «… не прикреплён: в таких файлах обычно хранятся пароли и ключи». В списке `@` и на плашке открытого файла они не предлагаются. Если агенту нужно что-то из такого файла, напишите в сообщении только то, что можно показать.

**Картинки понимают не все модели.** Claude, GPT и большинство современных моделей понимают. Если модель не умеет, вы увидите сообщение об этом — выберите другую модель.

## 11. Действия из редактора

**Выделенный код:** выделите фрагмент в редакторе → правая кнопка мыши → **dimosi** →
- **Объяснить** — агент объяснит, что делает код, ничего не меняя;
- **Исправить** — найдёт и исправит ошибки (с подтверждением);
- **Улучшить** — сделает код понятнее и надёжнее, не меняя поведения;
- **Добавить в чат** — прикрепит фрагмент к сообщению, а задачу вы напишете сами.

**Ошибки в коде:** если VS Code подчеркнул ошибку, наведите на неё или нажмите на лампочку 💡 → **Исправить с помощью dimosi**. Агент получит текст ошибки и код вокруг неё.

## 12. Ход работы и стоимость

- **План.** Для задач из нескольких шагов агент показывает карточку **«План»** с прогрессом: ✓ — сделано, синяя точка — делается сейчас.
- **Что происходит сейчас.** Внизу панели во время работы пульсирует линия из логотипа и написано текущее действие («Чтение index.html…», «Ждёт вашего решения…») и время.
- **Токены и стоимость.** Справа внизу: `токены 18 тыс. → 950 · ≈ 2.30 ₽ · контекст 18 тыс.`
  - первое число — сколько отправлено нейросети, второе — сколько она написала;
  - **стоимость**: для Polza AI это **точная сумма в рублях**, которую сообщает сам сервис; для Anthropic и OpenRouter — оценка в долларах по тарифу; для остальных — только токены;
  - **контекст** — размер разговора. Если он становится оранжевым, разговор слишком длинный: ответы дороже и медленнее. Для новой задачи начните **новый чат** (+).

**Как экономить:** новая задача — новый чат; для простых задач выбирайте модели подешевле (в названии часто есть `mini`, `flash`, `haiku`, `sonnet`). Для моделей Claude включено **кэширование**: и напрямую через Anthropic, и через Polza AI или OpenRouter. На каждом шаге агент заново отправляет весь разговор. Кэширование означает, что повторно отправленная часть стоит примерно в 10 раз дешевле. Первый запрос нового чата стоит чуть дороже обычного (запись в кэш ×1,25), зато каждый следующий шаг сильно дешевле. Кэш живёт 5 минут: если сделать паузу дольше, следующий шаг снова запишет его заново.

**Как проверить, что кэш работает:** откройте журнал (**View → Output → dimosi**). В строке каждого запроса после слова `in` в скобках написано, сколько взято из кэша, например `in 52000 (cache read 49800, write 1900, hit 96%) out 310`. Здесь `hit 96%` — доля разговора, взятая из кэша. Обычно она 80–99%, начиная со второго шага задачи. Если скобок нет, сервис не сообщил о кэше. Если Polza AI вдруг откажется принимать пометки кэша, dimosi сам повторит запрос без них и до перезапуска больше их не ставит. Работа не прервётся, просто станет дороже.

## 13. Смена сервиса, модели и ключей

Все команды — через палитру: `Cmd+Shift+P` (Windows: `Ctrl+Shift+P`), начните печатать **dimosi**:

| Команда | Что делает |
|---|---|
| **dimosi: Выбрать сервис и модель** | Сменить сервис и модель |
| **dimosi: Ввести API-ключ** | Добавить или заменить ключ |
| **dimosi: Удалить API-ключ** | Удалить сохранённый ключ |
| **dimosi: Экспортировать ключи в файл…** | Сохранить ключи в зашифрованный файл |
| **dimosi: Импортировать ключи из файла…** | Загрузить ключи из файла |
| **dimosi: Правила для агента** | Список правил и действия с ними |
| **dimosi: Открыть глобальные правила** | Открыть (или создать) файл правил для всех проектов |
| **dimosi: Новый чат** | Начать разговор заново; прежний чат уходит в прошлые |
| **dimosi: Прошлые чаты…** | Открыть или удалить один из прежних чатов этой папки ([раздел 7а](#7а-чат-сохраняется-сам)) |
| **dimosi: Переключить подтверждения действий** | Вкл/выкл подтверждения |
| **dimosi: Усердие модели…** | Насколько старательно модель работает ([раздел 7е](#7е-усердие-модели)) |
| **dimosi: Проверить обновления** | Проверить и поставить новую версию сейчас ([раздел 14а](#14а-обновления)) |
| **dimosi: Сообщить о проблеме** | Собрать отчёт для разбора ошибки ([раздел 18](#журнал-и-отчёт-о-проблеме)) |

Ключи нескольких сервисов можно хранить одновременно и переключаться в любой момент — разговор сохраняется.

**Настройки:** **Code → Settings → Settings** (Windows: **File → Preferences → Settings**), в поиске наберите `dimosi`. Все настройки dimosi:

| Настройка | По умолчанию | Что делает |
|---|---|---|
| **Provider** | `anthropic` | Через какой сервис работает агент: `anthropic`, `openai`, `polza`, `openrouter`, `deepseek`, `ollama`, `custom`. Удобнее менять командой **Выбрать сервис и модель** |
| **Model** | пусто | Имя модели. Пусто — модель сервиса по умолчанию (для Polza AI это `anthropic/claude-opus-5.5`) |
| **Custom Base Url** | пусто | Адрес своего сервера, только для `custom` ([раздел 16](#16-свой-сервер-или-локальная-нейросеть)) |
| **Approval Mode** | `ask` | `ask` — спрашивать подтверждение правок и команд; `auto` — не спрашивать ([раздел 8](#8-подтверждения-и-откат-изменений)) |
| **Max Steps** | 50 | Сколько шагов агент делает на одну задачу, прежде чем остановиться |
| **Sandbox** | включено | Песочница для команд агента на Mac ([раздел 17](#17-безопасность)). Выключайте, только если она мешает нужной команде, и включите обратно сразу после неё. На Windows не действует |
| **Effort** | пусто | Усердие модели: `low`, `medium`, `high`, `max`. Пусто — как решит сама модель. Удобнее менять командой **Усердие модели…** ([раздел 7е](#7е-усердие-модели)) |
| **Image Model** | пусто | Модель Polza AI, которая рисует картинки по просьбе агента. Пусто — `qwen/image-2` ([раздел 7д](#7д-создание-картинок)) |
| **Extra Folders** | пусто | Папки вне проекта, открытые агенту. Удобнее менять ссылкой **«Изменить»** в строке «Доступ» ([раздел 7б](#7б-папки-вне-проекта)) |
| **Auto Update** | включено | Ставить новые версии dimosi автоматически ([раздел 14а](#14а-обновления)) |

API-ключей в настройках нет: они хранятся в системном хранилище паролей (Keychain на Mac).

## 14. Перенос на другой компьютер

**Возьмите с собой:**
1. `dimosi-<версия>.vsix` с самым большим номером (из папки `dist`).
2. Файл с ключами: `Cmd+Shift+P` → **dimosi: Экспортировать ключи в файл…** → пароль → сохранить (`dimosi-keys.aienc`). **Запомните пароль** — восстановить его нельзя.
3. Глобальные правила, если вы их писали: файл `~/.config/dimosi/rules.md`. Чтобы найти его: **книга** → **Открыть глобальные правила** → правой кнопкой по вкладке файла → **Reveal in Finder**.
4. По желанию — `dimosi-cli-<версия>.tgz` для терминала.

**На новом компьютере:**
1. Установите или обновите VS Code (1.140+).
2. Установите расширение из `.vsix` ([раздел 4](#4-установка)).
3. `Cmd+Shift+P` → **dimosi: Импортировать ключи из файла…** → файл → пароль.
4. Глобальные правила: **книга** → **Открыть глобальные правила** → замените текст своим → сохраните.
5. Откройте папку проекта, выберите сервис и модель. Правила проекта лежат в самом проекте (`.dimosi/`) и переезжают вместе с ним.

## 14а. Обновления

**Расширение обновляется само.** Примерно раз в 6 часов (и через полминуты после запуска VS Code) dimosi проверяет сервер обновлений. Найдя новую версию, он:
1. проверяет **цифровую подпись** обновления: подписать его может только владелец своим ключом. Даже если сервер взломают, поддельное обновление не установится;
2. скачивает её и **проверяет контрольную сумму** (повреждённый или подменённый файл не установится);
3. если агент в этот момент работает над задачей — ждёт, пока он закончит;
4. устанавливает и показывает уведомление «dimosi обновлён до версии … — **Перезагрузить**». Нажмите, и через пару секунд работает новая версия. Ключи, правила и настройки сохраняются.

Проверить вручную: `Cmd+Shift+P` → **dimosi: Проверить обновления**.
Отключить автообновление: настройки → `dimosi` → снять галочку **Auto Update**.

**Терминальная версия** раз в сутки при запуске сообщает о новой версии. Обновление: `dimosi update` (на Mac может понадобиться `sudo dimosi update`).

> Обновления раздаются по секретной ссылке с сервера d-osi.ru. Ссылка зашита в установочный файл. dimosi — личный инструмент владельца: не передавайте `.vsix` другим людям.

> Настройки dimosi (сервис, модель, подтверждения, автообновление) действуют только из **ваших личных** настроек VS Code. Файл `.vscode/settings.json` чужого проекта их не изменит. В папках, которым VS Code не доверяет (режим ограниченного доступа), dimosi не работает.

## 15. Работа из терминала (необязательно)

1. Установите **Node.js 22.12 или новее** с [nodejs.org](https://nodejs.org) (кнопка **LTS**).
2. В терминале, в папке с файлом: `npm install -g ./dimosi-cli-<версия>.tgz` (подставьте номер из имени файла, например `0.4.4`) (на Mac может понадобиться `sudo` в начале).
3. Проверка: `dimosi --help`.

Основные команды:
```
dimosi keys set polza                         # сохранить ключ (спросит ключ и пароль хранилища)
dimosi keys import ~/Desktop/dimosi-keys.aienc
dimosi use polza anthropic/claude-opus-5.5    # сервис и модель по умолчанию
dimosi rules global                           # создать файл глобальных правил
cd путь/к/проекту && dimosi                   # открыть чат в папке проекта
dimosi "найди и исправь ошибку в app.js"      # сразу дать задачу
```

Терминальная версия ведёт журнал в файле `~/.config/dimosi/dimosi.log` (Windows: `%APPDATA%\dimosi\dimosi.log`). Команда `dimosi log` показывает, где он лежит, и его последние строки. Когда журнал дорастает до 1 МБ, он переименовывается в `dimosi.log.1`, и начинается новый.

Песочница для команд в терминальной версии тоже включена. Флаг `dimosi --no-sandbox` запускает чат без неё (осторожно).

Усердие модели ([раздел 7е](#7е-усердие-модели)) в терминале задаётся при запуске: `dimosi --effort high` (уровни: `low`, `medium`, `high`, `max`). Без флага модель решает сама.

Режим «Сначала план» ([раздел 7в](#7в-режим-сначала-план)) в терминале: запуск `dimosi --plan` или команда `/plan` внутри чата. Перед приглашением будет написано `план ›`. Когда агент покажет план, ответьте `/go`, чтобы он его выполнил, или напишите, что поправить.

Папки вне проекта ([раздел 7б](#7б-папки-вне-проекта)) в терминале открываются флагами. Их можно повторять:
```
dimosi --read-dir ~/notes                     # только чтение
dimosi --write-dir ~/work/shared              # чтение и запись
dimosi --read-dir ~/notes --write-dir ~/work/shared "сверь план с кодом"
```
При запуске dimosi покажет строку «Доступ: проект + 2 папки» и список. Команда `/folders` внутри чата показывает его снова. Чтобы не писать флаги каждый раз, добавьте список в файл `~/.config/dimosi/config.json`:
```
"extraFolders": [
  { "path": "/Users/вы/notes", "access": "read" },
  { "path": "/Users/вы/work/shared", "access": "write" }
]
```
Список в расширении VS Code и в терминале раздельный.

Терминальная версия читает те же правила, показывает план, изменения (зелёный/красный) и стоимость. Чтение страниц из интернета ([раздел 7г](#7г-чтение-страниц-из-интернета)) в терминале работает так же: про каждый новый сайт будет вопрос, ответ `a` запоминает сайт.

Ответ `a` на вопрос о команде запоминает её для этого проекта так же, как кнопка «Всегда» ([раздел 8](#подтверждения-прямо-в-чате)); список хранится в `~/.config/dimosi/allowed-commands.json`. Команда `/allowed` внутри чата показывает его, `/allowed remove НОМЕР` убирает одну запись, `/allowed clear` — все. Списки расширения и терминала раздельные.

Внутри чата: `/model`, `/models`, `/provider`, `/key`, `/rules`, `/folders`, `/allowed`, `/plan`, `/go`, `/auto`, `/ask`, `/clear`, `/help`, `/exit`. **Ctrl+C** во время работы останавливает агента.

Если стояла старая терминальная версия (`ai-agent`), её настройки и ключи переносятся автоматически при первом запуске `dimosi`. Старую версию можно удалить: `npm uninstall -g @api-ai/cli`.

## 16. Свой сервер или локальная нейросеть

**Ollama (бесплатно, на своём компьютере):**
1. Установите с [ollama.com](https://ollama.com).
2. В терминале: `ollama pull qwen3-coder` (или другую модель). Нужен мощный компьютер.
3. dimosi: **Выбрать сервис и модель** → **Ollama (local)** → модель.

Локальные модели слабее облачных и иногда плохо справляются с инструментами агента.

**Любой OpenAI-совместимый сервис (custom):** **Выбрать сервис и модель** → **Custom OpenAI-compatible** → адрес API (например, `http://localhost:1234/v1` для LM Studio) → при необходимости ключ → модель.

**Адрес должен начинаться с `https://`.** `http://` можно только для этого компьютера (`localhost`, `127.0.0.1`): по `http://` ключ и переписка шли бы по сети незашифрованными. Если адрес не подходит, dimosi напишет «Адрес сервиса … не подходит» и ничего не отправит. Для известных сервисов (Anthropic, OpenAI, Polza AI и др.) адрес задать нельзя: dimosi всегда шлёт ключ только на их официальный адрес.

## 17. Безопасность

- **Ключи** хранятся в защищённом хранилище системы: «Связка ключей» на Mac, «Диспетчер учётных данных» на Windows.
- **Файл экспорта** (`.aienc`) зашифрован (AES-256). Без пароля он бесполезен, но всё равно не публикуйте его.
- **Песочница для команд (Mac).** Команды агента выполняются за «забором», который ставит сама macOS (такой же использует Claude Code):
  - писать можно только в папку проекта, в папки, которые вы открыли агенту для записи ([раздел 7б](#7б-папки-вне-проекта)), во временные папки и в кэши пакетов (`~/.npm`, `~/Library/Caches` и подобные). Файлы в других местах команда не создаст и не испортит. Папки с установленными программами (`~/.cargo/bin`, `~/go/bin` и т. п.) тоже закрыты;
  - даже внутри проекта (и внутри папок, открытых для записи) нельзя менять `.vscode/`, git-хуки и настройки git (в том числе вложенных репозиториев), `.husky/`, `.envrc`, `.devcontainer/`, `.github/workflows/`: оттуда код может запуститься позже, уже без песочницы. И нельзя менять правила агента в `.dimosi/`;
  - нельзя запускать другие программы Mac через `open` и управлять ими через AppleScript: они работали бы уже без песочницы;
  - нельзя читать файлы проекта с паролями (`.env` и другие из списка ниже; образцы вроде `.env.example` можно). Если сборке или запуску проекта нужен `.env`, в песочнице она его не увидит: такую команду выполните сами в терминале;
  - фоновые программы, запущенные командой (`… &`), останавливаются вместе с ней. Сервер для разработки, который должен работать дольше, запустите сами в терминале;
  - читать нельзя ключи и личные папки: `~/.ssh`, `~/.aws`, `~/.git-credentials` (там git хранит токен GitHub), `.npmrc`, `.netrc`, `~/.config` (кроме настроек git), логины облачных сервисов и сборщиков (`~/.azure`, `~/.terraform.d`, `~/.gradle/gradle.properties`, `~/.m2/settings.xml` и др.), `~/.claude`, «Документы», «Рабочий стол», «Загрузки», «Изображения», iCloud Drive, Связку ключей, почту, сообщения, данные программ из App Store, Telegram, Slack, Bitwarden, браузеров (Chrome, Safari, Firefox, Яндекс, Brave, Arc, Edge), VS Code, VS Code Insiders, Cursor и VSCodium, настройки dimosi, настройки и историю терминала (`~/.zshrc` и подобные: туда часто записывают токены). Если проект или папка, которую вы открыли агенту, лежит, например, в «Документах», она остаётся доступной, а соседние нет;
  - интернет открыт: без него не работают `npm install` и `git fetch`.

  Если песочница что-то запретила, в выводе команды будет `Operation not permitted`, а агент объяснит, что случилось. Чего агент в песочнице **не сможет**: `git push` и другие действия с вашими паролями от GitHub, `git config` и `git remote add` в проекте. Такие команды выполните сами в терминале. На Windows песочницы нет, там остаются подтверждения.
- **Агент видит только папку проекта и папки, которые вы сами ему открыли** ([раздел 7б](#7б-папки-вне-проекта)). Инструменты агента и песочница для команд пользуются одним и тем же списком. Содержимое прочитанных и прикреплённых файлов отправляется выбранному сервису. Не открывайте агентом папки с паролями и личными документами.
- **Файлы с секретами агент не читает**, даже внутри проекта: `.env` и `.env.*` (кроме образцов `.env.example`, `.env.sample`, `.env.template`), `*.pem`, `*.key`, `*.p12`, ключи SSH (`id_rsa`, `id_ed25519`), `.npmrc`, `.netrc`, `secrets.json`, `credentials`, `release.config.json`, `wp-config.php` (пароль от базы WordPress), ключи Google (`service-account*.json`, `client_secret*.json`), `auth.json` (Composer), `.htpasswd`, `.my.cnf`, `.git-credentials`, `*.tfvars`, `*.tfstate`. Образец `wp-config-sample.php` агент читает. В поиске агента они тоже не участвуют, ярлык на такой файл тоже не читается, а менять их агент не может: попросит вас сделать это самим. Прикрепить их к сообщению тоже нельзя. Иначе их текст ушёл бы сервису ИИ. Если агенту что-то нужно из такого файла, он спросит вас: назовите ему имена настроек, но не сами значения.
- **Ключи не попадают в команды.** Перед запуском команды dimosi убирает из её окружения всё, что похоже на ключ или пароль: переменные, в имени которых есть `KEY`, `TOKEN`, `SECRET`, `PASS`, `PWD`, `CREDENTIAL`, `AUTH`, `DSN`, `COOKIE`, `SESSION`, и все, где в значении адрес с паролем (`postgres://user:пароль@…`). Если команде такой ключ всё же нужен (например, `npm publish` с `NPM_TOKEN`), запустите её сами в терминале.
- **Страницы из интернета** агент читает только с вашего разрешения для каждого сайта ([раздел 7г](#7г-чтение-страниц-из-интернета)): только `https://`, без входа в аккаунты, не с вашего компьютера и не из домашней сети. Если вы пользуетесь VPN, который подменяет адреса сайтов (так устроены многие программы), проверка «не из домашней сети» работает слабее: главной защитой остаётся ваше разрешение и то, что читаются только сайты с настоящим сертификатом.
- **Не отключайте подтверждения** в важных проектах: песочница защищает остальной компьютер, но внутри проекта команда может удалить или испортить файлы.
- **Чужие проекты.** Агенту велено считать содержимое файлов и вывод команд данными, а не указаниями. Правила чужого проекта (`AGENTS.md`, `CLAUDE.md`, `.dimosi/`) подключаются только после вашего «Доверять» ([раздел 9](#доверие-к-правилам-проекта)), а правка файлов, которые могут сами запускать команды, всегда спрашивается отдельно ([раздел 8](#особо-важные-файлы-всегда-с-отдельным-вопросом)).
- **Если ключ утёк** — удалите его в кабинете сервиса и создайте новый.

| В строке «Доступ» написано «не подключено: 1» | Папка из списка не найдена (удалена, переименована, отключён диск) или её нельзя открывать. Наведите мышь на строку, чтобы увидеть причину. Уберите папку через **«Изменить»** или верните её на место |
| Агент выполнил команду без вопроса, хотя подтверждения включены | Раньше вы нажали **Всегда** для такой команды в этом проекте. Три точки **«…»** в заголовке панели → **Запомненные команды** → выберите команду → **Забыть** ([раздел 8](#подтверждения-прямо-в-чате)) |
| Нажал «Всегда», а агент снова спрашивает про похожую команду | Запоминается начало команды (оно написано на кнопке), а команды из нескольких частей (`&&`, `;`, `|`) и команды, которые запускают другую программу (`npm exec …`, `docker run …`, `curl …`), — только целиком. Опасные команды спрашиваются всегда |
| Раньше нажал «Всегда для «npm exec …»», а после обновления агент снова спрашивает | С версии после 0.5.0 такие широкие разрешения больше не действуют: по ним прошла бы любая программа. Нажмите «Всегда» ещё раз: запомнится команда целиком. Старую строку можно убрать в списке запомненных команд |
| После правки файла агент пишет об ошибках, которых вы не видите, или не замечает видимых | Агент получает то, что VS Code показывает во вкладке **Problems** для этого файла сразу после правки ([раздел 7](#7-как-работать-с-агентом)). Если проверка языка в VS Code ещё запускалась (первые секунды после открытия проекта) или проект большой и проверка идёт дольше 4 секунд, ошибки могли не успеть: попросите агента запустить сборку или тесты |
| Во время работы агента в строке вкладок на секунду появляется и исчезает вкладка с файлом | Так задумано: VS Code проверяет на ошибки только файлы во вкладках, поэтому dimosi открывает изменённый файл в фоне и закрывает после проверки ([раздел 7](#7-как-работать-с-агентом)) |
| Агент ничего не меняет и пишет, что включён режим плана («Plan mode is on») | Включена кнопка **«Сначала план»** под полем ввода. Нажмите **«Выполнить план»** на карточке под ответом или выключите кнопку ([раздел 7в](#7в-режим-сначала-план)) |
| Агент пишет, что страницу прочитать нельзя: «Only https», «not IP addresses», «local network» | Читаются только обычные сайты по адресу `https://` ([раздел 7г](#7г-чтение-страниц-из-интернета)). Страницу с вашего компьютера или из домашней сети сохраните в файл проекта и попросите агента прочитать файл |
| Сайт разрешён через «Всегда», а dimosi снова спрашивает про страницу, карточка с жёлтой рамкой | В адресе после `?` больше 100 знаков ([раздел 7г](#7г-чтение-страниц-из-интернета)). Проверьте, что в адресе нет данных из проекта, и решите |
| Агент пишет «The site answered 403» или получил пустой текст | Сайт не отдаёт страницу программам или рисует её в браузере. Скопируйте нужный текст со страницы в чат |
| Агент пишет, что адрес «redirects to another site» | Страница переехала на другой сайт. Агент попросит разрешение для нового сайта: проверьте адрес и решите |
| Карточка подтверждения не реагирует | Нажмите **Стоп** и повторите задачу |
| Карточка с предупреждением «Внимание: скрытые символы» | В команде или изменении есть невидимые знаки ([раздел 8](#подтверждения-прямо-в-чате)). Если не понимаете зачем, нажмите **Отклонить** и спросите агента |
| «Адрес сервиса … не подходит: нужен адрес, который начинается с https://» | В настройке **Custom Base Url** (в терминале — `--base-url`) укажите адрес с `https://`. `http://` можно только для `localhost` и `127.0.0.1` ([раздел 16](#16-свой-сервер-или-локальная-нейросеть)) |
| В терминале: «--base-url можно задать только для custom и ollama» | У известных сервисов свой адрес, менять его нельзя. Для своего сервера выберите `custom` |
| «Файл обновлений слишком большой» или «повреждён» | С сервером обновлений что-то не так, обновление не установлено. Ничего делать не нужно: dimosi проверит снова позже. Если повторяется несколько дней, соберите отчёт о проблеме |
| При выпуске: «Для коммита … на GitHub нет проверки CI» | Коммиты ещё не отправлены. Выполните `git push`, дождитесь зелёной галочки на вкладке **Actions** и запустите выпуск снова ([раздел 19](#19-для-разработчика-как-пересобрать)) |
| При выпуске: «CI … ещё идёт» | Подождите 5–10 минут и запустите выпуск снова |
| При выпуске: «CI … не зелёный» | Проверка на GitHub упала. Откройте ссылку из сообщения, посмотрите, какой тест упал, исправьте (или попросите агента), отправьте исправление и дождитесь зелёной галочки |
| При выпуске: «Не удалось узнать статус CI» | Нет интернета или GitHub недоступен. Повторите позже. В крайнем случае: `--skip-ci` ([раздел 19](#19-для-разработчика-как-пересобрать)) |
| При выпуске: «…исчерпан лимит запросов с вашего адреса» | GitHub без входа отвечает на 60 запросов в час с одного адреса в интернете, а с VPN этот адрес общий с другими людьми. Интернет в порядке. Запустите выпуск снова после времени, указанного в сообщении (или выключите VPN на минуту). `--skip-ci` для этого не нужен |
| `npm run test:vscode` пишет «timed out waiting…» | Настоящий VS Code не успел запустить проверку. Повторите команду. Если повторяется, отправьте вывод тому, кто помогает |
| «Неверный пароль» при импорте | Нужен пароль, заданный при экспорте. Если забыт — экспортируйте заново на старом компьютере |
| Логотипа нет на левой панели | **Extensions** → вкладка **Installed** → проверьте, что «dimosi» установлен и включён, перезапустите VS Code |
| Ошибка о версии при установке `.vsix` | Обновите VS Code до 1.140+ |
| Обновление не пришло | `Cmd+Shift+P` → **dimosi: Проверить обновления** — покажет причину. Проверьте, что в настройках включено **Auto Update** |
| «dimosi: не удалось обновиться…» | Если VS Code отказался ставить обновление своей командой, dimosi сам пробует поставить его через командную строку VS Code; в сообщении и в журнале (**View → Output → dimosi**) написана причина. В крайнем случае поставьте вручную: **Extensions → … → Install from VSIX…** → файл из папки `dist` проекта |
| `dimosi: command not found` в терминале | Установите CLI ([раздел 15](#15-работа-из-терминала-необязательно)) и перезапустите терминал |
| Непонятная ошибка или агент «странно себя ведёт» | Соберите отчёт о проблеме (ниже) и отправьте тому, кто помогает |

### Журнал и отчёт о проблеме

dimosi ведёт **журнал**: что и когда он делал. Там записаны запуск и версия, смена сервиса и модели, каждый запрос к нейросети (сервис, модель, размер, сколько длился, код ответа, повторы, сокращение длинного разговора), вызовы инструментов (какой, сколько длился, была ли ошибка), проверки и установка обновлений.

**В журнал никогда не попадают** API-ключи, текст переписки и содержимое файлов. Даже если сервис вернёт ключ в сообщении об ошибке, dimosi заменит его на `[ключ скрыт]`.

**Посмотреть журнал:** меню **View → Output** (Вид → Вывод), справа в выпадающем списке выберите **dimosi**.

**Отправить отчёт о проблеме:**
1. `Cmd+Shift+P` (Windows: `Ctrl+Shift+P`) → наберите **dimosi: Сообщить о проблеме** → Enter.
2. Внизу справа появится уведомление с двумя кнопками:
   - **Скопировать в буфер обмена** — затем вставьте отчёт (`Cmd+V`) в письмо или мессенджер;
   - **Сохранить в файл…** — выберите место (по умолчанию Рабочий стол), файл `dimosi-report-ДАТА.txt` можно приложить к письму.

В отчёте: версии dimosi, VS Code и системы, настройки dimosi (без ключей; для своего сервера — только адрес без пути), для каких сервисов сохранены ключи (только названия), последняя ошибка и последние 500 строк журнала.

## 19. Для разработчика: как пересобрать

Нужен Node.js 22.12+.

```
cd api-ai
npm install          # зависимости
npm test             # автотесты: ядро, откат, панель, сквозные проверки VS Code и CLI
npm run test:vscode  # проверка в настоящем VS Code (см. ниже)
npm run typecheck    # проверка типов
npm run package      # dist/dimosi-<версия>.vsix и dist/dimosi-cli-<версия>.tgz
```

**Автоматическая проверка на GitHub (CI).** При каждой отправке кода на GitHub (`git push`) GitHub сам устанавливает зависимости (`npm ci`), проверяет типы, запускает все тесты и проверку в настоящем VS Code на Linux и macOS. Результат виден на странице репозитория во вкладке **Actions**: зелёная галочка — всё хорошо, красный крестик — что-то сломалось (нажмите на него, чтобы увидеть, какой тест упал). Настройка лежит в `.github/workflows/ci.yml`. Секреты для этого не нужны.

**Сквозные проверки** запускаются вместе с остальными тестами (`npm test`), без интернета и без настоящих ключей:
- `packages/vscode/test/e2e/` — настоящая логика панели чата работает поверх заглушки VS Code (`vscode.ts`) и фейкового OpenAI-совместимого сервера (`fakeServer.ts`). Сценарии: задача → подтверждение записи → откат; «Стоп» во время команды; ошибка 429 → повтор; переполнение контекста; восстановление чата после перезагрузки окна;
- `packages/cli/test/cli.test.ts` — собирает терминальную версию во временную папку (без адреса обновлений) и даёт ей задачу с ответами через ввод.

**Проверка в настоящем VS Code** (`npm run test:vscode`). Обычные тесты работают на заглушке VS Code, а эта проверка запускает настоящий:
- при первом запуске скачивает VS Code 1.140.0 (самую старую версию, которую поддерживает dimosi; на диске займёт около 900 МБ) в папку `.vscode-test` проекта. Папка в git не попадает;
- на 20–30 секунд открывается отдельное окно VS Code с пустым профилем и без других расширений. Ваш VS Code, его настройки и ключи не затрагиваются. Окно закроется само, трогать его не нужно;
- в этом окне проверяется: расширение запускается, все команды на месте, панель чата открывается, агент выполняет задачу (вместо нейросети отвечает фейковый сервер на этом же компьютере), файлы записываются, ошибки редактора для JSON и TypeScript доходят до модели, ваша вкладка остаётся впереди;
- в конце в терминале будет строка `✔ dimosi works in the real VS Code` или красная строка с тем, что не так;
- сервер обновлений и настоящие нейросети не используются;
- другую версию VS Code можно проверить так: `DIMOSI_VSCODE_VERSION=stable npm run test:vscode`.

**Выпуск новой версии** (установленные копии обновятся сами):
1. Закоммитьте все изменения: выпуск возможен только из чистой рабочей папки, чтобы каждая версия совпадала с коммитом.
2. Отправьте коммиты на GitHub (`git push`) и дождитесь зелёной галочки на вкладке **Actions** (обычно 5–10 минут). Выпуск возможен только с коммита, который прошёл проверку на GitHub: скрипт сам спрашивает GitHub и останавливается, если проверки нет, она ещё идёт или она красная.
3. Запустите выпуск:
   ```
   npm run release                                  # следующая версия: 0.4.4 → 0.4.5
   npm run release -- 0.5.0 --notes "Что нового"   # своя версия и описание (до 500 символов)
   ```
4. Скрипт проверяет CI, поднимает версию, прогоняет тесты и проверку типов и собирает расширение. Это занимает минуту-две. Если тесты или сборка не прошли, версия возвращается обратно, на сервер ничего не уходит.
5. Когда проверки прошли, скрипт попросит **ключ подписи**: «Проверки прошли. Вставьте ключ подписи из Bitwarden и нажмите Enter». Откройте Bitwarden, запись «dimosi — ключ подписи», скопируйте пароль, вставьте в терминал (символы не отображаются) и нажмите Enter. Ключ спрашивается только сейчас, чтобы он был в памяти лишь несколько секунд и его не видела ни одна программа из сборки. Если ключ не подошёл, версия возвращается — просто запустите выпуск заново.
6. Скрипт подписывает `latest.json`, заливает файлы на сервер (`latest.json` — последним) и проверяет, что новая версия скачивается и подпись сходится.
7. В конце скрипт сам делает коммит `Release X.Y.Z` и метку `vX.Y.Z`. Отправьте их на GitHub: `git push && git push --tags`.

Если GitHub не работает, а выпуск срочный, проверку CI можно пропустить: `npm run release -- 0.5.0 --notes "…" --skip-ci`. Скрипт напишет, что выпуск не проверен на GitHub. Пользуйтесь этим только в крайнем случае: локальные тесты всё равно запустятся, но проверки на Linux и в настоящем VS Code не будет.

**Ключ подписи** создаётся один раз командой `npm run signing-key`. Закрытая часть записывается в файл `dimosi-signing-key.txt` в закрытой временной папке (не на Рабочем столе: он может копироваться в iCloud). Скрипт напечатает две готовые команды: `open -e "…"` — открыть файл, и `rm -r "…"` — удалить папку. Перенесите ключ в Bitwarden и выполните вторую команду. Открытая часть хранится в `packages/core/src/update-key.ts` и встраивается в расширение.
- Закрытый ключ **нельзя** класть в проект, на сервер и куда-либо ещё, кроме Bitwarden.
- **Если ключ потерян или украден:** выполните `npm run signing-key -- --add`, выпустите версию старым ключом (если он ещё есть) и удалите старый открытый ключ из `update-key.ts` в следующем выпуске. Если старого ключа нет совсем, установленные копии новые обновления не примут: новую версию придётся один раз поставить вручную из `.vsix`.

Для выпуска нужен файл `release.config.json` в корне проекта (образец — `release.config.example.json`). В нём секретный адрес обновлений и SSH-доступ. **Файл в git не попадает** — не коммитьте его: репозиторий публичный. Сохраните копию файла рядом с ключами сервера: без него выпускать обновления на тот же адрес нельзя.

Сервер: файлы лежат в `/var/www/dimosi-updates` (юзер `deploy`), раздаёт их nginx сайта d-osi.ru отдельным блоком `location` (см. `deploy/nginx/d-osi.ru.conf` в проекте сайта).

Устройство:
```
packages/core      ядро: сервисы нейросетей, цикл агента, инструменты, правила, стоимость, шифрование ключей
packages/vscode    расширение: src/ — логика, webview/ — интерфейс панели, media/ — стили и логотип
packages/cli       программа для терминала
```

- **Новый сервис:** добавить в `PRESETS` (`packages/core/src/providers/presets.ts`) и в `enum` настройки `dimosi.provider` (`packages/vscode/package.json`).
- **Логотип и цвета:** `packages/vscode/media/brand/` (иконки) и переменная `--brand` в `packages/vscode/media/chat.css`.
- **Отладка:** откройте `packages/vscode` в VS Code, `npm run build`, затем `F5`.
