# CLAUDE.md — правила работы с dimosi

dimosi — AI-агент для программирования: расширение VS Code и CLI. Личный инструмент владельца, другим людям не раздаётся. Репозиторий публичный: github.com/dimosiev/api-ai-vscode.

## Состояние (обновляй после каждого выпуска)

- Версия **0.5.4**, выпущена 3 октября 2026 (создание картинок через Polza AI, `generate_image`: владелец проверил на живом ключе; в списке моделей только разговорные и умеющие инструменты; понятные ошибки для рисующих моделей и пустого ответа). 0.5.3 — после выключения VPN запросы к сервису модели идут напрямую, в ошибке «Нет связи» видна причина. 0.5.2 — (решения владельца по аудиту: в режиме плана не выполняются никакие команды; «Документы» и `~/Library` целиком не открываются; на сайте с «Всегда» адрес с длинной частью после `?` спрашивается). 0.5.1 — исправления ошибок аудита О-1…О-9. Номер хранится в `package.json` всех пакетов, `npm run release` поднимает его сам.
- 612 тестов, CI: ubuntu-latest и macos-latest, включая проверку в настоящем VS Code.
- Аудит после 0.5.0 (`docs/AUDIT.md`) закрыт: открытых находок и тестов `bug(...)` нет. Идёт обкатка в обычной работе владельца; новое добавлять после неё.
- Требования: VS Code 1.140+, Node.js 22.12+.
- Владелец работает в основном через **Polza AI**, модель по умолчанию `anthropic/claude-opus-5.5` (у Anthropic напрямую — `claude-opus-5-5`).

## Владелец и общение

- Владелец не программист. Пиши ему по-русски и простыми словами, без жаргона; термин, без которого не обойтись, поясняй.
- В отчётах давай ссылки на код в виде `файл:строка`.
- Пошаговые инструкции для владельца: где что нажать и что он увидит. Команды для терминала — готовыми к вставке.
- Давай рекомендацию, а не обзор вариантов. Спрашивай только то, что решает владелец.
- Честно пиши, что проверено, а что нет (настоящий VS Code, Windows, живые API).

## Главные принципы

- **Стабильность прежде всего.** Просто, надёжно, без лишней сложности и без новых зависимостей. Если зависимость всё же нужна, бери последнюю версию, совместимую с остальными.
- **Каждое исправление закрепляй тестом.** Ошибку, найденную по ходу работы, сначала воспроизведи тестом (он должен упасть), потом исправляй.
- **Работай по одной задаче:** план в 2–3 фразах → код → тесты → `npm test && npm run typecheck && npm run build` → документация → отдельный коммит на `main`.

## Запреты и секреты (обязательно)

- `release.config.json` (секретный адрес обновлений и SSH) не коммить и не выводи его содержимое. Если адрес нужен в скрипте, читай его из файла, а в выводе маскируй.
- Закрытый ключ подписи хранится только в Bitwarden владельца. Никогда не проси вставить его в чат и не ищи его на диске.
- Сервер обновлений — прод-сервер сайта d-osi.ru. На нём ничего не меняй, только читай (например, проверяй `latest.json`).
- `npm run release` не запускай: ключ вставляет владелец в своём терминале. Ты даёшь ему точную команду.
- Пуш на GitHub делай только после явного «да» владельца на этот пуш.
- Ответы Claude (`Message.providerData.raw`) в истории не изменяй никогда: ни при обрезке контекста, ни при сохранении или восстановлении чата. Иначе API отклонит запрос. Менять можно только сообщения пользователя и результаты инструментов.
- Перед коммитом проверяй, что в изменениях нет ключей и секретного адреса.

## Команды

```
npm install                     # зависимости (Node 22.12+)
npm test                        # vitest: все тесты, включая сквозные (без сети и ключей)
npm run typecheck               # tsc: core, cli, vscode, webview
npm run build                   # сборка расширения и CLI в dist/ пакетов
npm run test:vscode             # настоящий VS Code 1.140.0 (качается в .vscode-test), на ~30 с открывает отдельное окно
npm run package                 # dist/dimosi-<версия>.vsix и dist/dimosi-cli-<версия>.tgz
npx vitest run <часть имени>    # один файл тестов
AUDIT_STRICT=1 npx vitest run audit   # показать настоящие падения тестов bug(...)
```

Выпуск (только владелец): сначала `git push` и зелёный CI (скрипт сам проверяет коммит `HEAD` на GitHub и иначе останавливается), потом `npm run release -- X.Y.Z --notes "…"`, затем `git push && git push --tags`. `--skip-ci` — только если GitHub недоступен.

## Настройки расширения

`dimosi.provider` (`anthropic` | `openai` | `polza` | `openrouter` | `deepseek` | `ollama` | `custom`, по умолчанию `anthropic`), `dimosi.model` (пусто — модель сервиса по умолчанию), `dimosi.customBaseUrl`, `dimosi.approvalMode` (`ask` | `auto`), `dimosi.maxSteps` (50), `dimosi.sandbox` (true), `dimosi.imageModel` (модель Polza AI для картинок; пусто — `qwen/image-2`), `dimosi.extraFolders` (`[{ "path", "access": "read" | "write" }]`, пусто), `dimosi.autoUpdate` (true). Все с `"scope": "application"`: действуют только из личных настроек, `.vscode/settings.json` проекта их не меняет. Ключи — в SecretStorage (Keychain), не в настройках. Новая настройка: рецепт в `docs/ARCHITECTURE.md`, раздел 6. Свой адрес сервиса — только для `custom`/`ollama` и только `https://` (http — для localhost), проверка в `checkBaseUrl` (`presets.ts`).

## Устройство

Подробно, с путём одного сообщения, таблицей «что нельзя сломать» и рецептами типовых задач: **`docs/ARCHITECTURE.md`. Прочитай его перед правкой модуля** и исправляй в том же коммите, если поменял устройство. Здесь только карта.

Монорепозиторий на npm workspaces, TypeScript, сборка esbuild, тесты vitest.

- `packages/core/src` — ядро, общее для VS Code и CLI. Не импортирует `vscode`: всё, что зависит от хоста (вопросы владельцу, файлы, ошибки редактора, хранилища), приходит через интерфейсы.
  - `agent.ts` — цикл агента: запросы, повторы, обрезка контекста, `restore()`, режим «Сначала план» (`planFirst` → `PermissionGate.planOnly`).
  - `access.ts` — единое правило доступа (`AccessPolicy`): проект плюс папки вне проекта. Им пользуются и инструменты (`resolvePath`), и песочница (`sandboxProfile`): менять доступ только здесь.
  - `permissions.ts` — подтверждения (`PermissionGate`), особо важные файлы (`protectedPathWarning`), опасные команды (`dangerousCommandWarning`): спрашиваются всегда, даже в `auto`.
  - `commandRules.ts` — что запоминает «Всегда» для команды (по началу или целиком).
  - `tools/index.ts` — инструменты; `tools/sandbox.ts` — песочница macOS и окружение команд без ключей; `tools/workspace.ts` — обход файлов и `isSecretFile`; `tools/web.ts` — `fetch_page`; `tools/image.ts` — `generate_image` (картинки через Media API Polza AI, всегда с вопросом владельцу).
  - `prompt.ts` — системная инструкция; `rules.ts` — правила и доверие к ним; `providers/` — Anthropic SDK и OpenAI-совместимые сервисы, `presets.ts` — список сервисов.
  - `log.ts` — журнал с маскировкой ключей; `update.ts`, `update-key.ts` — подписанные обновления (Ed25519); `secrets.ts` — файл ключей.
- `packages/vscode/src` — расширение: `extension.ts` (команды), `chatView.ts` (панель чата), `approval.ts` (карточки подтверждения), `editorFiles.ts` (правки через редактор), `problems.ts` (ошибки редактора после правки), `changes.ts` (откат), `chatStore.ts` (`chat.json`), `access.ts`, `commandRules.ts`, `ruleTrust.ts`, `updater.ts`, `vsixInstall.ts`, `report.ts`, `errorText.ts`, `directFetch.ts` (запрос напрямую, если прокси VS Code не отвечает), `pictures.ts` (картинка для панели). `protocol.ts` — сообщения между расширением и панелью.
- `packages/vscode/webview` — интерфейс панели (браузерный код).
- `packages/cli/src` — терминальная версия. Журнал: `~/.config/dimosi/dimosi.log`.
- `scripts/` — выпуск, упаковка, ключ подписи.
- `docs/РУКОВОДСТВО.md` — руководство для владельца. `docs/AUDIT.md` — аудиты и таблица «Исправлено».

Главное, что нельзя сломать (полная таблица с тестами — в `docs/ARCHITECTURE.md`, раздел 5):

- Начало запроса стабильно внутри чата: системная инструкция, набор инструментов, ранние сообщения. Иначе сбрасывается кэш. Режим плана и пометки для модели идут в сообщение пользователя.
- Доступ решается только в `access.ts`. Секретные файлы (`.env`, ключи) агент не читает, не меняет, не прикрепляет.
- Составная команда (`&&`, `;`, `|`, `$(…)`…) и программа, запускающая другую (`RUNS_ANOTHER`, `RUNS_ANOTHER_AFTER`, `curl`/`wget`), по началу не проходят никогда. Не ослабляй без теста.
- Панель чата недоверенная: команды только из `PANEL_COMMANDS` (`chatView.ts`), пути через `resolvePath`.
- Ничего тяжёлого в процессе расширений без лимита: поиск идёт в отдельном потоке, разбор веб-страницы линейный (`stripMarkup`, без регулярных выражений по всей странице).
- Кэш у Anthropic — `cache_control` на весь запрос; через OpenAI-совместимый путь для моделей с `claude` в имени — пометки на системной инструкции и последнем сообщении, при 400 они выключаются до перезапуска. Проверка — `hit N%` в журнале.

## Тесты: как писать

- Файлы: `packages/*/test/**/*.test.ts`.
- Ошибку, которую не исправляешь сразу, закрепи тестом `bug(...)` (зелёный, пока ошибка есть) и запиши в `docs/AUDIT.md`; после исправления замени на `it(...)`.
- Код расширения тестируется на заглушке `vscode`: `packages/vscode/test/e2e/vscode.ts`. В `vitest.config.mts` её подключает alias. Управление заглушкой — через объект `stub`. Если коду понадобился новый API VS Code, добавь его в заглушку.
- Модули, которые не должны импортировать `vscode` (`chatStore`, `textEdit`, `report`, `errorText`, `protocol`), держи такими, чтобы их можно было тестировать напрямую.
- Сквозные тесты используют фейковый OpenAI-совместимый сервер: `packages/vscode/test/e2e/fakeServer.ts`.
  - VS Code: `test/e2e/chat.test.ts` — настоящий `ChatViewProvider` поверх заглушки.
  - CLI: `packages/cli/test/cli.test.ts` собирает `cli.js` во временную папку с пустым адресом обновлений и вводит ответы через stdin.
- Настоящий VS Code: `packages/vscode/test/real/` (`run.mjs` собирает расширение без адреса обновлений и запускает `suite.ts` внутри VS Code; это не файл vitest). Поведение редактора, которое нельзя угадать (вкладки, диагностика), сначала измерь там, потом повтори в заглушке.
- Тесты никогда не обращаются к серверу обновлений и к настоящим API.
- **Без фиксированных пауз.** CI на перегруженных машинах медленнее: ожидание пиши через опрос условия с запасом до ~5 с (`eventually`, `diesWithin`), а не через `setTimeout(…, 100)`.
- Проверка на нестабильность: запусти несколько `npx vitest run` одновременно.

## Документация после каждой задачи

- `docs/РУКОВОДСТВО.md`: пошагово, по-русски, для не-программиста — где нажать и что будет. Если появилась новая ошибка или сообщение, добавь строку в раздел 18 «Если что-то не работает».
- `docs/AUDIT.md`: перенеси пункт в таблицу «Исправлено» и обнови число тестов.
- `README.md`: только если изменились возможности или команды.
- `docs/ARCHITECTURE.md`: если изменилось устройство, путь сообщения, правило из таблицы «что нельзя сломать» или рецепт.
- `CLAUDE.md`: если изменились правила работы, настройки или появилась новая ловушка. После выпуска обнови раздел «Состояние».
- Раз в несколько выпусков сверяй `prompt.ts` и описания инструментов (`tools/index.ts`) с актуальными рекомендациями Anthropic по промптам: убирай устаревшее и закрепляй изменения тестами. Автоматически скачивать правила при работе dimosi нельзя: инструкция должна быть стабильной (кэш, тесты, защита от чужих указаний).

## Коммиты

- Отдельный коммит на задачу, на ветке `main`. Сообщение по-русски: заголовок и список изменений.
- Последняя строка: `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- Перед пушем проверь `git status`: в рабочей папке не должно быть чужих изменений.

## Известные ловушки

- `npm run test:vscode` из терминала VS Code или из расширения: скрипт сам убирает переменные `ELECTRON_RUN_AS_NODE` и `VSCODE_*`, иначе новый VS Code запускается как обычный Node. На Linux без экрана нужен `xvfb-run -a`.
- На компьютере владельца VPN подменяет адреса всех сайтов на 198.18.x.x. Поэтому `isPublicAddress` считает этот диапазон публичным; не «чини» это без проверки на настоящем сайте.
- VS Code шлёт запросы расширений через системный прокси и помнит его для каждого сайта до 5 минут. У владельца прокси — это VPN (`127.0.0.1:1082`): после его выключения запросы уходили в никуда. Поэтому сервисы моделей вызываются через `directFetch.ts`. Обновления (`updater.ts`) и `fetch_page` пока идут обычным `fetch`.
- `gh` не установлен. Статус CI смотри через публичный API: `curl -s "https://api.github.com/repos/dimosiev/api-ai-vscode/actions/runs?head_sha=$(git rev-parse HEAD)"`. Ошибки упавшего job: `.../check-runs/<job_id>/annotations`. Полные журналы без входа недоступны.
- Для пуша файлов `.github/workflows/` токену GitHub нужно право `workflow`. Владелец уже выдал новый токен; если пуш снова отклонят с этой ошибкой, объясни владельцу, как выпустить токен заново.
- VS Code 1.140 бывало отклонял `workbench.extensions.installExtension` значением без текста. Поэтому есть запасная установка через CLI, а ошибки выводятся через `errorText()`, никогда через `(e as Error).message`.
- Чтобы вручную поставить расширение владельцу: `"/Applications/Visual Studio Code.app/Contents/Resources/app/bin/code" --install-extension dist/dimosi-X.Y.Z.vsix --force`. Сначала сверь SHA-256 файла с подписанным `latest.json` на сервере.
- Библиотека OpenAI сама повторяет запросы при 429/5xx. Эти повторы не видны в журнале агента.
- Этот файл (`CLAUDE.md`) dimosi тоже читает как правила проекта. После каждой правки файла dimosi снова спросит владельца, доверять ли ему. Держи файл коротким: в dimosi он уходит в каждом запросе.
- Системные модальные окна VS Code (`showWarningMessage` с `modal: true`) не прокручиваются. Длинный текст в `detail` выталкивает кнопки за край экрана. Пиши туда пару строк, а длинное открывай в редакторе.
- Песочница macOS (`tools/sandbox.ts`) запрещает командам писать вне проекта (кроме временных папок и кэшей — именно кэшей, не папок с программами), читать личные папки и содержимое секретных файлов проекта (кроме зависимостей: `node_modules`, `.venv`…), запускать программы через `open`/Apple Events. Новой программе нужна ещё одна папка для записи — добавь её в `HOME_WRITABLE` и закрепи тестом. После правки профиля проверь вручную на копии проекта `npm ci`, сборку и git: правило на папку `credentials` однажды уже ломало `npm ci`. Копию клади в `~`, а не во временную папку (туда писать можно всегда); `npm run build` в песочнице падает на `release.config.json` (секретный файл) — это ожидаемо, для проверки сборки убери его из копии. Если dimosi сам запущен в песочнице (например, тесты из Claude Code), вложенная не стартует: тогда каждая команда спрашивается с предупреждением, даже в `auto`.
- Любое изменение начала запроса сбрасывает кэш: системной инструкции (дата, правила), набора инструментов, ранних сообщений. Обрезка старых результатов инструментов делается редко и сразу пачкой. Проверка — `hit N%` в журнале.

## Что не сделано (из AUDIT.md)

- Windows в CI. Песочница для Windows и Linux.
- Желательные пункты Ж-1 (вариант 2), Ж-2, Ж-3, Ж-5, Ж-6, Ж-8, Ж-10, Ж-11, Ж-13.
- Медиа: видео, музыка и озвучка (тот же Media API Polza AI; видео готовится минутами — нужен показ хода); картинки через OpenRouter; правка картинки по образцу (`images` на вход); стоимость картинок в общем счётчике чата.
- Экономия, следующие шаги: переключатель «усердия» модели (`output_config.effort`; через Polza — как передать, проверить); правила вне системной инструкции (дата уже берётся один раз на чат; правка `CLAUDE.md` или `.dimosi/` посреди чата всё ещё сбрасывает кэш); для прямого Anthropic — серверная очистка контекста вместо правки истории (новые модели привязывают размышления к неизменной истории).
- План после 0.4.7 (по порядку): переключатель «усердия» (нужна проверка через Polza на живом ключе); правила вне системной инструкции (нужно решение владельца). Папки вне проекта, «Всегда» по началу команды, ошибки редактора, тест в настоящем VS Code, выпуск с зелёного CI, режим «Сначала план», чтение веб-страниц, Ж-9, Ж-1 (вариант 1), Ж-7 и дата один раз на чат сделаны.
